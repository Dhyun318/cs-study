# CS 차곡 일러스트 스타일

## 목적과 공통 규칙
인터랙티브 시뮬레이션과 별개로, CS 개념을 매력적인 정지 그림으로 전달한다. 2026-11-14 사용자 결정으로 A 정돈된 도식을 전체 세트의 확정 스타일로 채택했다. B는 비교 기록으로 보존한다. 두 방향 모두 라이트 테마, 투명 배경, 390px viewBox, 좌우 여백 24px, 한국어 최소 라벨을 사용한다. 기존 루트 SVG와 preview.png는 첫 파일럿 기록으로 보존했다.

주황은 배경과 작은 강조에만 쓴다. 의미는 색 외에도 라벨과 사물 관계로 전달한다. 원본 도서의 그림, 구도, 문장과 예시 값을 복제하지 않는다. 이번 제작에서는 도서 그림을 열지 않았다.

## A 정돈된 도식 · 채택
- 위치: `a/<sim id>.svg`, 목표 30KB 미만.
- 전체 31개 시뮬레이션 id마다 하나의 SVG를 작성한다. labels와 예시 값은 해당 notes의 [[sim:id]] 주변 설명을 기준으로 한다.
- 기존 파일럿의 도형 규칙을 유지한다. 기존 context-switch와 tcp-handshake는 유지했고 hash-collision은 notes의 예시로 조정했다.
- 반경 24px의 묶음, 12~18px의 노드, 반경 12px 단계 번호. 선 2px, 둥근 끝, 열린 V 화살촉.
- 흰색과 회색 면을 중심으로 정보를 구조화하고, 중요한 블록은 남색으로 채운다.
- 그림자, 그라데이션, 입체 사물을 쓰지 않는다. 관계와 순서의 명료함을 우선한다.
- 제목 24px / 700, 주요 라벨 14~18px / 600, 설명 12~13px / 500.

## B 일러스트 · 미채택
- 위치: `b/<sim id>.svg`, 목표 80KB 미만. 이번 세트는 모두 직접 작성한 벡터이며 래스터 이미지를 사용하지 않았다.
- 기준 크기 390×500px. 큰 사물 하나와 보조 사물 둘을 중심으로 충분한 여백을 둔다.
- 부드러운 2.5D: 사선 약 27도의 타원과 다각형으로 상단·옆면·앞면을 만든다. 상단은 밝고, 오른쪽 면은 진한 파랑, 전면은 중간 파랑이다.
- 배경 전체를 카드로 감싸지 않는다. 흐릿한 원형 광원, 바닥 타원, 얇은 점선 경로로 공간을 만든다.
- 흰색에서 옅은 파랑으로 이어지는 표면 그라데이션과 파랑 그라데이션을 사용한다. 남색은 CPU와 서버의 깊은 면에 제한한다.
- 그림자는 SVG feDropShadow, dy 8px, stdDeviation 7px, 남색 opacity .12. filter 영역을 넉넉하게 잡아 잘림을 막는다.
- 주요 사물의 윤곽을 모두 선으로 감싸지 않는다. 경로와 작은 세부에만 1.2~4px 선을 쓴다. 모서리는 가능한 한 둥글게 표현한다.
- 사물 어휘: 해시 버킷과 키 태그, 연결 고리, CPU 칩과 메모리 보관함, 노트북과 서버 랙, 패킷 봉투.
- 제목 21px / 700, 라벨 13~14px / 600, 기술 용어 11~12px / 600. 작은 보조 설명은 핵심 의미를 대신하지 않는다.
- 사물은 개념 비유다. PCB가 실제 외장 메모리 카트리지라는 뜻이나 TCP 메시지가 실제 편지라는 뜻으로 해석하지 않도록 title과 desc에 개념을 설명한다.

## 글꼴과 사용 방식
새 SVG의 font-family는 `Pretendard, -apple-system, sans-serif`이며 글꼴 데이터, @font-face, 외부 이미지, 스크립트를 포함하지 않는다. 텍스트는 편집 가능한 text 요소로 유지한다.

앱이 로드한 Pretendard를 그대로 쓰려면 SVG를 인라인으로 삽입한다. img 요소로 넣은 외부 SVG는 호스트 페이지의 글꼴을 상속하지 않으므로, 로컬에 Pretendard가 없으면 시스템 글꼴로 대체된다. SVG마다 글꼴을 다시 내장하지 않는다. compare.html은 SVG를 인라인으로 넣고 페이지에서 Pretendard를 한 번 공유 로드한다. 오프라인에서는 시스템 글꼴로 대체되며 도형과 텍스트 내용은 유지된다.

독립 파일에는 title, desc, role=img, aria-labelledby를 둔다. 여러 SVG를 인라인으로 넣을 때 gradient, filter, title, desc 등 ID에 고유 접두어를 붙인다. 비교 페이지에는 이미 적용했다.

## 구성과 개념 범위
- hash-collision: 채택 A는 notes의 키 1032와 1039, h(k)=k % 7, 버킷 3을 사용한다. 체이닝은 버킷의 연결 리스트로 표현한다. 미채택 B와 루트 첫 파일럿은 과거 비교 기록이므로 14·26, mod 6 예시를 유지한다.
- context-switch: A의 PC와 레지스터를 PCB A에 저장하고 PCB B의 문맥을 복구한 뒤 B를 실행한다. B에서 같은 CPU와 두 보관함을 사용한다. PCB의 다른 관리 정보와 프로세스별 전체 메모리 배치는 생략한다.
- tcp-handshake: SYN, SYN+ACK, ACK의 방향과 순서를 유지한다. 일반적인 순차 종료 FIN, ACK, FIN, ACK 및 능동 종료 측 TIME_WAIT를 함께 표시한다. B는 연결을 주 그림으로, 종료는 하단 보조 설명으로 둔다. 동시 open/close, 재전송, FIN/ACK 결합, 구체적인 sequence 번호는 범위 밖이다.

확신이 부족한 개념 사항은 없다. 위 생략은 정지 그림의 명시적인 범위다.

## 전체 갤러리와 보존 기록
compare.html은 채택 A 31개를 자료구조 8개, 운영체제 10개, 데이터베이스 6개, 네트워크 7개로 묶은 Figma형 캔버스다. 프레임 제목은 한국어 개념명과 id다. 390px 폭을 유지하고 넓은 화면은 행당 3개, 그보다 좁은 화면은 행당 2개를 배치한다. 작은 화면에서는 캔버스를 가로로 스크롤한다. 연결선은 왼쪽에서 오른쪽으로 이어지고 행 끝에서 다음 행 첫 프레임으로 돌아온다. resize 시 연결선을 다시 계산하며 라이브러리는 사용하지 않는다.

과목이 겹치는 process-memory와 deadlock은 운영체제에 각각 한 번만 배치했다. 동일 SVG를 해당 notes의 다른 과목에서도 사용할 수 있다. 정지 그림은 개념의 핵심 단면을 설명하며 시뮬레이션의 모든 조작과 상태를 한 장에 담지는 않는다.

preview.html과 루트 SVG는 첫 파일럿 비교 기록, b/는 미채택 방향 기록이다. 과거 compare.png와 compare-mobile.png도 비교 당시 기록으로 남긴다. 현재 전체 갤러리 캡처는 gallery.png다. 앱 연결과 배포는 수행하지 않는다.

## 전체 세트 검증
2026-11-14, headless Chrome에서 31개 SVG의 XML 파싱과 독립 렌더링을 모두 확인했다. 내장 글꼴과 외부 이미지가 없고 모두 30KB 미만이다. 시스템 글꼴의 독립 SVG와 공유 Pretendard가 적용된 갤러리 양쪽에서 모든 텍스트의 렌더링 경계가 캔버스 안에 있었다.

1600px와 390px viewport에서 프레임 폭 390px, 과목 그룹 4개, 프레임 31개, 읽기 순서 연결선 27개, 인라인 SVG ID 중복 없음, 좁은 화면 가로 탐색을 확인했다. 페이지 및 콘솔 오류는 0건이었다. 네 과목의 전체 그림을 캡처해 육안 검토했다. 상세 파일 크기와 개념 범위는 REPORT.md를 참고한다. 실제 모바일 기기는 별도로 검증하지 않았다.

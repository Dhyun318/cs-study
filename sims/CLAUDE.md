# sims/ 시뮬레이션

개념을 단계별로 움직여 보는 화면 모음. 기준 문서: `../docs/features.md` 2절, 후보 목록 `../docs/simulations.md` 2절.
참고 구현: `hash-table/index.html`. 새 시뮬레이션은 `_kit/template.html`에서 시작한다.

## 결정 (2026-11-14)
- 빌드 없는 정적 파일: 순수 HTML/CSS/JS, 프레임워크·번들러·npm 없음, 모바일 390px 기준. 이유: 여러 에이전트가 동시에 만들어도 부딪히지 않고, 파일만 열면(file:// 포함) 바로 돈다. 버린 대안: React/Vite(빌드·의존성·공용 설정이 생겨 병렬 작업이 서로 막힌다), 한 파일에 전부(동시 편집 충돌).
- 시뮬레이션 하나 = 폴더 하나 = `sims/<id>/index.html` 한 파일(CSS·JS 인라인). 공용 코드는 `_kit/`에만 둔다. 다른 시뮬레이션 폴더와 `_kit/`은 고치지 않는다(필요하면 보고만).
- 단계 엔진은 단계 배열 + render 하나(단계마다 그림 상태를 통째로 담는다). 이유: 이전/다음/자동 재생이 번호 이동뿐이라 되감기 버그가 없다.
- 사본 금지(사용자 결정, 앱을 Vercel에 공개 배포): 책 문장, 책 예시 값, 책 그림 구도를 그대로 따라 그리기 금지. 개념만 쓴다. 아래 내용 규칙 참고.

## 폴더 이름(id)
- id는 `docs/simulations.md` 표의 첫 열(id)을 그대로 쓴다. `notes/`의 `[[sim:<id>]]` 표시도 같은 id를 쓰므로 바꾸지 않는다.
- 예외: `hash-storage`와 `hash-collision`은 하나로 합쳐 `hash-table` 폴더 하나로 만들었다(완료). 앱은 두 id를 `hash-table`로 연결한다.

## 만드는 순서
1. `cp _kit/template.html <id>/index.html`
2. 머리: `<title>`, `<h1>`, 관련 질문 링크. 질문이 둘이고 모드로 나뉘면 링크마다 `data-mode="모드 이름"`.
3. 단계 배열과 `render` 작성. 모드(예: TCP/UDP, Lock 켜기/끄기)가 있으면 `modes`로.
4. 직접 해 보기 form: 지금 보이는 단계(`Sim.step()`)에서 이어지는 단계를 만들어 `Sim.load`.
5. `sims/index.html`에 한 줄 등록.
6. 검사(아래).

## kit API (`_kit/kit.js`, `_kit/kit.css`)
- `Sim.start({ steps: [...], render })` 또는 `Sim.start({ modes: { 이름: [...], 이름2: [...] }, render })`. 모드가 둘 이상이면 탭이 생긴다.
- 단계 = `{ caption: '설명', ...그림에 필요한 값 }`. `render(step, stage)`가 `#sim-stage`에 그린다(보통 `stage.innerHTML = ...`).
- `Sim.load(steps)` 단계 바꾸고 1단계부터, `Sim.play(true|false)` 자동 재생, `Sim.step()` 지금 단계, `Sim.reset()` 지금 모드 처음으로.
- 마크업 약속: `#sim-stage`, `.sim-q[data-q]`, `[data-mode]`, `form.sim-try`. 탭, 단계 번호, 설명, 이전/재생/다음 버튼은 kit이 붙인다.
- ←/→ 키, 자동 재생이 끝에서 멈추기, 움직임 줄이기 설정(애니메이션 끔)은 kit이 처리한다. 새로 들어온 것 강조는 `.sim-pop`.

관련 질문 링크: `data-q="<content 파일 이름>/<그 파일 ### 질문 순번, 1부터>"` (예: `02-data-structure/12`). 지금은 kit이 원문 md로 보낸다. 앱 질문 화면 주소가 생기면 `kit.js`의 `qUrl` 한 줄만 바꾼다.

## 내용 규칙
- 개념은 근거 그림(`_reference/simulations-full.md`의 그림 파일)과 `_reference/content/` 본문에 있는 것만. 책에 없는 사실을 더하지 않는다. 그림은 개념을 이해하려고 보는 것이다.
- 사본 금지: 책 문장을 옮기지 않는다. 설명은 직접 쓴 문장. 예시 값(숫자, 이름, key, 주소, 표 크기)은 직접 고른다. 책 그림의 배치를 그대로 따라 그리지 않는다. 관련 질문 링크 글자도 책 질문 문장이 아니라 직접 지은 짧은 주제 이름.
- 원 출판사 이름과 브랜딩은 쓰지 않는다(그림 속 ID, 예시 값 포함).
- 설명: 한 단계에 한두 문장, 해요체, 50자 안팎. 숫자나 변수 바로 뒤에 조사를 붙이지 않는다(받침에 따라 틀린다). 예: `${k}는` 대신 `계산해 보니 ${at}번 칸이에요.`
- 예시 계산은 실제로 맞는 값만. 결과를 지어내지 않는다(필요하면 계산법을 직접 정하고 예시라고 밝힌다).

## 스타일 규칙
- 색은 `kit.css` 변수만. 라이트 테마만. 주황·노랑 글자 금지(별은 `.sim-star`). `--red`는 충돌·오류 표시에만.
- em dash, en dash, 큰따옴표는 쓰지 않는다.
- 아이콘은 Tabler 모양만(kit에 있는 것 재사용).
- 390x844 한 화면에 그림, 설명, 이전/재생/다음이 같이 보이게. 문서 가로 스크롤 금지. 넘칠 수 있는 줄은 `flex-wrap`으로 접는다.
- 사용자 입력은 숫자·선택만 받거나 `textContent`로 넣는다(입력 글자를 innerHTML에 넣지 않는다).

## 목록 등록 (`sims/index.html`)
맞는 과목 `<ul>` 안에 한 줄. 별 = 관련 질문 중 가장 많은 별 수, 별 없는 질문이면 `sim-star` span을 뺀다. 다른 에이전트와 동시에 고칠 수 있으니 저장 직전에 다시 읽고 내 줄만 넣는다.
```html
<li><a href="<id>/index.html"><span class="sim-star" aria-label="별 N개">N</span>시뮬레이션 이름</a></li>
```

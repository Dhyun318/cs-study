# 기능 정의

모바일로 CS 공부하는 앱. 면접 연습 앱이 아니라 공부 자료 앱이다(2026-11-14 결정).
내용 출처는 `notes/*.md`(같은 개념을 우리 말로 새로 쓴 해설, 40문항 + 꼬리질문, ⭐ = 기출 빈도). 책 원문은 `_reference/content/`(git 제외).

우선순위: **1차** = 처음 만들 때 꼭 필요, **나중** = 1차를 써 보고 필요하면 추가.

---

## 1. CS 내용 보기

책처럼 읽는 기능. 앱의 중심.

| 기능 | 우선 | 없으면 안 되는 이유 |
|---|---|---|
| 목차: 과목 > 주제 > 질문 | 1차 | 40문항을 찾아 들어갈 길이 없다 |
| 질문 상세: 질문, 답변 본문, 이미지, 꼬리질문 | 1차 | 공부할 본문 자체 |
| 답 가리기 / 펼치기 | 1차 | 바로 답이 보이면 스스로 떠올려 보는 공부가 안 된다 |
| 이어 읽기 (마지막 위치 기억) | 1차 | 짧게 여러 번 여는 모바일에서 매번 다시 찾게 된다 |
| 읽음 표시 + 과목별 진도 | 1차 | 어디까지 했는지 모르면 같은 걸 반복한다 |
| 질문 끝 읽음으로 표시 / 읽음 취소 | 1차 | 2026-11-14 결정. 끝까지 읽어도 읽은 시간이 짧으면 자동으로 읽음이 안 되어 손으로 표시할 길이 필요하다. 취소한 질문은 자동 판정으로 다시 쌓지 않는다 |
| 진행 칸 옆 남은 단락 표시 (예: 남은 3단락) | 1차 | 2026-11-14 사용자 요청. 스크롤할 때 얼마나 남았는지 글로도 보여 준다 |
| ⭐ 빈출 모아 보기 (별 많은 순) | 1차 | 시간 없을 때 무엇부터 볼지 정해 준다 |
| 헷갈림 표시 → 목차의 "헷갈림만" 거르기로 복습 | 1차 | 모르는 것만 다시 보는 게 가장 효율적인 공부. 2026-11-14 결정으로 별도 복습 화면 대신 목차에서 거른다 |
| 공통 헤더: 앱 이름(홈으로) + 홈 · 목차 · 시뮬레이션 탭, 하위 화면은 뒤로 버튼 | 1차 | 2026-11-14 사용자 요청. 어느 화면에서든 한 번에 홈·목차로 갈 수 있어야 한다 |
| 홈의 "헷갈림 n문항 다시 보기" 줄 (헷갈림이 1개 이상일 때만, 누르면 목차 헷갈림만) | 1차 | 2026-11-14 결정. 복습 입구가 목차 안에만 있으면 찾기 어렵다 |
| 랜덤 질문 (홈) | 1차 | 2026-11-14 사용자 요청. 아무 질문이나 하나 꺼내 바로 떠올려 보는 연습 |
| 이전 / 다음 질문 이동 | 1차 | 목차로 돌아갔다 오면 흐름이 끊긴다 |
| 검색 (deadlock, index 같은 개념어) | 나중 | 40문항이면 목차로 충분, 늘어나면 추가 |
| 북마크 | 나중 | 헷갈림 표시와 역할이 겹친다. 따로 필요하면 추가 |
| 기출 모의면접 문항 모음 (1~4회) | 나중 | 원문에 있는 자료라 읽기 화면만 재사용하면 된다 |
| 글자 크기 조절 | 나중 | 기기 설정으로 대부분 해결 |

## 2. CS 시뮬레이션 보기

글로 읽기 어려운 개념을 움직이는 그림으로 보고 직접 눌러 보는 기능.
질문 상세 화면 안에 "동작으로 보기"로 붙이고, 시뮬레이션만 모아 보는 목록도 둔다.

| 기능 | 우선 | 없으면 안 되는 이유 |
|---|---|---|
| 단계별 재생 (이전 / 다음 / 자동 재생) | 1차 | 한 번에 다 움직이면 따라갈 수 없다 |
| 단계마다 한 줄 설명 | 1차 | 그림만으로는 무엇이 일어났는지 모른다 |
| 직접 입력해 보기 (값 넣기, push/pop 누르기) | 1차 | 보기만 하면 읽는 것과 차이가 없다 |
| 시뮬레이션 ↔ 해당 질문 본문 연결 | 1차 | 본 다음 바로 글로 정리해야 기억에 남는다 |

**범위 (2026-11-14 결정):** 책(PDF)에 실린 그림만 움직이는 시뮬레이션으로 만든다. 책에 그림이 없는 개념은 만들지 않는다.
후보 목록과 근거 그림은 `docs/simulations.md`가 기준이다(2026-11-14 결정: 책 그림의 시뮬레이션을 전부 만든다. 후보 22개 + 정적 그림 재검토분).
질문만 보고 뽑았던 초안 중 책에 그림이 없는 것(Array 삽입·삭제, Stack 두 개로 Queue, open addressing, process state 전이, B+tree vs 전체 스캔, join 결과 표)은 버렸다.

## 3. CS 공부 알림 보내기 (뺌)

2026-11-14 사용자 결정으로 이번 범위에서 뺐다. 프론트만 만들면 앱을 닫은 상태의 알림은 서버 없이 불가능하고, 대안(폰 달력 반복 일정 .ics)도 이번에는 넣지 않는다. 다시 넣게 되면 달력 반복 일정 방식이 1순위.

## 4. 공통

| 기능 | 우선 | 없으면 안 되는 이유 |
|---|---|---|
| 진도·헷갈림·마지막 위치 저장 (기기 안, localStorage) | 1차 | 앱을 닫으면 다 사라진다 |
| 진도 초기화 (읽음·헷갈림 모두 지우기, 한 번 더 확인) | 1차 | 2026-11-14 결정. 한 바퀴 다 읽고 처음부터 다시 공부할 때 필요 |
| 오프라인 지원 (서비스 워커로 본문·시뮬레이션·글꼴 저장) | 1차 | 2026-11-14 결정. 지하철 등 인터넷 없는 출퇴근길 공부. 전체 약 1MB. 서비스 워커 app/sw.js, 경로는 모두 상대 경로(앱이 /app/ 아래로 옮겨질 예정) |
| 홈 화면 | 1차 | 이어 읽기, 랜덤 질문, 과목 진도, ⭐ 빈출, 시뮬레이션 진입점을 모으는 곳 |
| 랜딩 페이지 (첫 주소 /, 앱은 /app/) | 1차 | 2026-11-14 사용자 요청. 처음 온 사람에게 폰 속 앱 화면이 스크롤에 맞춰 움직이는 소개로 무엇을 하는 앱인지 보여 준다. 공부 기록이 있으면 시작하기 버튼이 이어서 공부하기로 바뀐다(자동 이동 없음, 2026-11-14 결정) |
| 로그인·기기 간 동기화 | 안 함 | 프론트만 만든다(2026-11-14 결정). 서버 없음, 모든 데이터는 localStorage |
| 다크 모드 | 나중 | 디자인 취향이 라이트(오픽 앱 기준) |

## 화면 목록 (디자인 대상)

1. 홈: 이어 읽기, 랜덤 질문, 과목 진도, ⭐ 빈출, 시뮬레이션 바로가기
2. 목차: 과목 > 주제 > 질문, 읽음·헷갈림 표시, "헷갈림만" 거르기(복습)
3. 질문 상세: 질문, 답 가리기/펼치기, 본문·이미지, 꼬리질문, 헷갈림 표시, 이전/다음, 동작으로 보기
4. 시뮬레이션: 그림, 단계 재생, 단계 설명, 직접 입력, 관련 질문으로 가기
5. (뺌, 2026-11-14) 별도 복습 화면은 없애고 목차의 "헷갈림만" 거르기로 대신한다

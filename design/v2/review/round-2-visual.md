### 1-1. AI 티 없음, 개성 (15/20)

좋은 점: 홈의 과목 탑(homeMid)은 이 앱에서만 볼 수 있는 화면이다. 반쯤 찬 블록, 빨간 테두리 블록, 과목마다 다른 탑 높이가 데이터 그대로 그림이 되고, 공유 이미지(og.png)까지 같은 그림으로 이어진다. 흰 바탕 + 8px 회색 띠 + 선 없는 목록은 지금 앱(회색 바탕 위 흰 상자 더미)보다 훨씬 운영 중인 서비스에 가깝다.

감점 사유
- **히어로 그림 띠 왼쪽 절반이 비어 있다(-2, 구조).** home, home0, homeDone, offline, storageOff, update 모두 높이 120 띠의 왼쪽 약 45% 가 연한 파랑 빈 면이고 사물은 오른쪽에 몰려 있다. 1회차에는 이 자리에 조각 B 가 얹혀서 비워 둔 것이었는데(`illustrations.md` 4.1 `The left 40% is empty background`), 01-home 0절에서 조각을 뺀 뒤에도 구도 문장이 그대로 남았다. 글은 띠 아래에 있으니 왼쪽 빈 면은 할 일이 없고, 문구가 빠진 배너처럼 보인다. PNG 를 넣어도 같은 프롬프트라 그대로 남는다.
- **마크가 햄버거 메뉴로 읽힌다(-1.5, 구조).** 머리 왼쪽 위 19 x 16 의 가로 알약 3개(`index.html` 70행 `.mark`)는 앱에서 메뉴 버튼이 놓이는 바로 그 자리, 그 모양이다. 처음 연 사람은 누르면 메뉴가 열린다고 기대한다. 같은 막대 3개가 히어로 장면 오른쪽 끝에도 서명처럼 박혀 있어(`illustrations.md` 4.1 마지막 줄) 홈 첫 화면 200px 안에 같은 기호가 두 번 나온다. 그림 안의 로고 도장은 클립아트 결이다.
- **시뮬레이션 목록이 작은 도식 견본판이다(-1).** 2열 30칸이 모두 같은 연한 파랑 판 위에 남색·파랑 도식을 줄여 넣은 모양이라, 한 칸 한 칸은 다르지만 멀리서 보면 같은 질감의 격자다. 도식 안 글자가 6~8px 로 줄어 읽히지 않는 잔무늬가 된다. 도식을 줄여 쓰는 결정은 확정이라 방식은 두고, 1-6 의 잘림 처리로 덜 어수선하게 만드는 것만 요구한다.
- **카드마다 같은 3단 리듬(-0.5).** 히어로, 랜덤 카드, 질문 머리, 시뮬레이션 머리가 모두 `파랑 작은 분류 줄 / 굵은 제목 / 회색 메타` 순서다. 한 화면에 셋이 겹치면(home.png 히어로 + 랜덤) 템플릿 반복으로 보인다.

PNG 가 들어가면 풀릴 것과 아닌 것
- 풀릴 것: 대체 그림의 결이 서로 다른 점(loadFail 구름과 notFound 책은 선 그림, confEmpty 와 히어로는 면 그림, toc 의 자료구조 기호는 테두리, 네트워크 기호는 꽉 찬 원), 사물이 단순 도형뿐이라 생기는 밋밋함.
- 안 풀릴 것: 위 히어로 빈 왼쪽, 장면 안 마크 도장(둘 다 프롬프트에 적혀 있음), 머리 마크 모양.

### 1-4. 모션 (8/10)

문서는 1회차 지적을 모두 받았다: 이징 4개, 시간 4개, 바뀐 것만, 50% 보일 때 시작, `+1` 글자 없음, 답 펼침 240ms 하나, 되튐은 `pop` 자리 셋에만. 이 정도면 실서비스 수준이다.

감점 사유
- **분할 선택 흰 조각을 `scaleX` 로 늘린다(-1).** `index.html` 171행 `.segc .th` 는 폭 10px, 모서리 18px 인 요소를 `scaleX` 로 키운다. 모서리와 그림자까지 가로로 늘어나서, 정지 화면에서도 알약이 아니라 귀가 비뚤어진 사각형이 되고 그림자가 바탕 판 밖으로 번진다(1-5 첫 항목). transform 만 쓴다는 규칙을 지키려다 모양을 망친 경우다. 두 쓰임(목차 3칸, 시뮬레이션 2칸) 모두 칸 폭이 같아(`flex: 1`) `translateX` 만으로 충분하다.
- **움직임을 볼 증거가 없다(-1).** 이번 회차는 화면 채점인데 탑 쌓기, 답 펼침, 분할 조각 이동, 시뮬레이션 단계 넘김을 담은 움직이는 기록이 없다. 정지 화면으로는 9.3 표가 실제로 그렇게 도는지 판정할 수 없다.

### 1-6. 구현 가능성 (8/10)

좋은 점: 안전 영역, `100dvh`, 최대 폭, `theme-color`, `verify.py` 의 넘침·말줄임 자동 검사까지 갖췄다. 1회차 빠진 것 목록이 대부분 문서와 시안으로 들어왔다.

감점 사유
- **포스터 고정 viewBox 가 도식을 아무 데서나 자른다(-1).** `index.html` 568행 `viewBox="12 100 366 275"` + `slice`. 04-sims-list 4절은 한 값으로 모두 첫 판이 잡힌다고 했지만 30장 중 여럿이 아래 끝에서 잘린다: Linked List(아래 글 한 줄이 반만 보임), Heap(트리 12, 5 노드가 잘림), Dynamic Array(둘째 판 칸이 잘림), Hash 저장과 충돌(왼쪽 아래 남색 도형 조각), Process 간 통신(아래 막대 조각), table 용어와 key 종류(아래 글 줄 잘림). 잘린 글자 반쪽은 실수로 읽힌다. `verify.py` 는 `svg` 를 검사에서 빼서(CHECK 의 `el.closest('pre,.tbl,.jump,svg,iframe')`) 이걸 못 잡는다.
- **홈 시뮬레이션 카드가 360 에서 옆까지 잘린다(-0.5).** 640행 viewBox `12 100 366 167`(비 2.19) 을 높이 160 고정 칸에 `slice` 로 넣어, 카드 안쪽 폭 320(비 2.0)에서는 좌우가 잘리고 안쪽 판이 카드 테두리에 붙는다(360 homeEnd).
- **대체 그림이 그대로 출시될 수 있다(-0.5).** `illustrations/ready.js` 의 `ILL_READY = []`. PNG 11장이 끝내 안 나오거나 결이 안 맞아 탈락하면 지금 대체 그림이 실제 화면이 된다. 대체 그림도 출시 가능한 품질이어야 하는데 지금은 결이 섞여 있다.

### 1-7. 레퍼런스 도입 (8/10)

좋은 점: 근거 없는 이름을 표에서 뺐고(00 13절), 가져오지 않은 것과 이유까지 적었다. 이 정리는 실무 문서 수준이다.

감점 사유: 화면으로 보면 정체성의 대부분이 토스 TDS 에서 온다(회색 띠, 분할 선택, ListRow, 하단 막대, 회색 단계)(-1). 그 위에 이 앱 것은 탑과 블록 줄 정도다. 오픽에서 가져온 남색 CTA 와 큰 글자 탭은 확정이라 문제 삼지 않는다. 브릴리언트 이어 하기 카드에서 가져온 그림 + 제목 + 진행 + 버튼 구성은 맞게 옮겼지만, 브릴리언트는 그림이 띠 전체를 채운다(빈 왼쪽 없음)(-1).

### 1-8. 사용자 목적 부합 (9/10)

공부 자료 결이 화면에 잘 선다. 질문 화면은 리더 앱이고, 목차는 교재 목차이며, 게임 손맛(밀기, `+1`)이 빠졌다. 1차 범위 밖 기능은 보이지 않는다. 감점: 시뮬레이션 목록이 학습 입구라기보다 기술 문서 썸네일 모음으로 보여 처음 온 사람이 무엇을 누를지 고르기 어렵다(-1).

## 3. 90점에 도달하려면 반드시 고쳐야 할 것 (우선순위 순)

1. **분할 선택 조각을 진짜 알약으로(00 5.7, `index.html` 171행).** `scaleX` 를 빼고 조각 폭을 칸 폭으로 둔다: `.th { width: calc((100% - 8px) / var(--n)) }`, 이동은 `translateX(calc(var(--i) * 100%))` 하나. 칸이 모두 `flex: 1` 이라 폭이 같아 가능하다. 7장을 다시 찍어 양 끝이 바깥 판과 동심인지, 그림자가 판 밖으로 번지지 않는지 본다. 14절 점검표의 모서리 규칙 판정도 다시 한다.
2. **포스터 잘림을 의도된 모양으로(04 4절, `index.html` 568·640행).** (a) 포스터 그림에 아래 페이드를 깐다: `.pf svg { mask-image: linear-gradient(#000 80%, transparent) }`. 잘린 글 반쪽이 사라지고 아래로 이어지는 도식처럼 읽힌다. (b) 홈 카드는 높이 160 고정 대신 `.pf { aspect-ratio: 366 / 167 }` 로 viewBox 와 같은 비율을 써서 360 에서 옆이 잘리지 않게. (c) `verify.py` 에 포스터 검사를 더한다: 360 에서 30장을 찍어 눈으로 한 번 본다.
3. **답을 열기 전 질문 화면을 채운다(03 4절 와이어, 5.2).** 떠올리기 판을 하단 막대까지 늘린 답 자리로 만든다: 본문을 세로 flex 로 두고 판에 `flex: 1` + `min-height: 240`, 판 안 위쪽에 그 과목 기호 `sym-<과목>` 48(이미 있는 자리), 그 아래 `먼저 떠올려 보세요` 와 안내 한 줄, 판 맨 아래에 `답 보기`. 새 글도 새 그림도 없고 답도 새지 않으며, 화면이 문제 카드 앞면처럼 선다. 102자 제목(qLong)과 375 x 667 에서 판 최소 높이만 지키는지 찍어 본다.
4. **히어로 장면 구도를 다시 쓴다(`illustrations.md` 4.1, 대체 SVG).** 구도 문장을 `All objects sit inside the middle 70% of the frame, horizontally centered` 로 바꾸고, 장면마다 들어간 오른쪽 끝 `small stack of three flat rounded bars` 를 지운다. 대체 SVG 도 같은 배치로 옮긴다. 띠는 과목 표지이지 로고 자리가 아니다.
5. **머리 마크를 메뉴 아이콘과 구분한다(00 5.1 마크, 11절).** 가장 싼 방법: 머리에 마크 대신 이미 있는 앱 아이콘 타일(`brand/favicon.svg`, 남색 둥근 사각 안 막대)을 22~24 로 쓴다. 타일 안의 막대는 로고로, 맨 몸의 막대 3개는 메뉴로 읽힌다. 마크 자체를 바꾸려면 탑처럼 세로로 쌓인 블록(같은 폭, 맨 위 하나만 파랑, 블록 사이 틈이 보이게)으로.
6. **대체 그림을 출시 가능한 한 벌로(`illustrations.md` 4.2·4.3 대체 그림 열).** `ILL_READY` 가 비어 있는 한 대체 그림이 실제 화면이다. 상태 3장(notFound 책, loadFail 구름)과 기호 4장을 히어로·confEmpty 와 같은 면 그림(흰 면 + `--accent` 면, 선 굵기 하나)으로 맞춘다. PNG 가 들어와 결이 맞으면 그때 바꾼다.
7. **첫 화면 글자 위계(01-home 4.3, 00 3.2).** 랜덤 카드 제목을 `head` 19/650 에서 `row` 17/600 으로 내려 히어로 `title-2` 와 두 단계 차이를 만든다(토큰 안에서 해결, 목록 행과도 같은 크기라 일관). 질문 머리 위 줄(03 5.1)은 빈출 꼬리표를 정보 줄 앞으로 옮긴다: `[★4] 약 4분 · 꼬리질문 2`. 위 줄은 주제와 위치 글만 남아 360 에서 고아 꼬리표가 없어진다.
8. **목록 행 최소 높이(00 5.8).** 64 를 빼거나 52 로. 위아래 12 + 제목 26 = 50 이라 누르는 영역 44 는 그대로 넘는다. 한 줄 행 아래 빈 틈이 없어져 목차 리듬이 고르게 된다.
9. **다 읽음 히어로는 탑으로(01-home 5절, 06 해당 장면).** homeDone 띠에 과목 장면 대신 홈 탑과 같은 블록 4열(모두 `--accent`, 헷갈림은 빨간 테두리 그대로)을 그린다. 공유 이미지와 같은 그림이라 새 자산이 아니고, `40문항을 모두 쌓았어요` 를 말 그대로 보여 준다.
10. **남은 값 정리.** (a) A안 SVG 31장의 hex 5개를 토큰 값으로 치환(#596273→#4E5968, #EAF1FF→#EAF1FE, #E3E6EB→#E5E8EB, #F2F3F5→#F2F4F6, #F7F9FC→#FFFFFF 또는 `--band`). 스타일 결정은 그대로, 값만. (b) `.empty` 좌우 24→20. (c) 공유 이미지에 11절 표대로 빈출 꼬리표 하나를 넣거나 표에서 그 말을 지운다.
11. **모션 증거를 남긴다.** 탑 쌓기, 답 펼침, 분할 조각 이동, 시뮬레이션 단계 넘김 넷을 390 에서 짧은 영상(gif 또는 webm)으로 찍어 `shots/motion/` 에 둔다. 다음 회차 모션 점수는 이것으로 매긴다.

1~9 를 고치고 PNG 11장이 2절 프롬프트 결대로 나오면 시각 렌즈 점수는 88~91 범위로 본다. 90 을 넘기는 마지막 몫은 PNG 의 실제 품질에 달려 있다.

## 4. 좋은 점 (짧게)

- 과목 탑과 블록 줄: 데이터가 곧 브랜드 그림이고, 홈, 목차 장 머리, 공유 이미지까지 한 언어로 이어진다.
- 1회차 상투 모양 네 가지를 모두 걷어냈고, 핵심 답변의 형광펜은 이 앱의 표시로 자리 잡았다.
- 읽기 화면(qa, resume, qEnd)은 글자 크기, 줄 간격, 코드 판, 꼬리질문 펼침까지 리더 앱 수준이다.
- 상태 장면(초기화 시트, 되돌리기 알림, 오프라인 안내, 저장 깨짐 안내, 시뮬레이션 실패)이 실제 화면으로 다 있다. 문구도 토스 톤으로 고르다.
- 시뮬레이션 하단 막대: 375 x 667 에서도 마지막 단계 결과와 버튼이 한 화면에 들어온다.

1. 분할 선택 조각이 찌그러져 있고(7장), 포스터가 글자 반쪽을 자르며(목록 여러 장, 360 홈 카드), 운영 서비스라면 출시 전 QA 에서 걸리는 손질 결함이 핵심 화면에 보인다.
2. 일러스트 11자리가 아직 대체 그림이고 그 결이 선·면으로 섞여 있으며, 히어로 띠 왼쪽 절반은 PNG 가 와도 비게 되어 있다. 그림이 서야 하는 학습 앱(브릴리언트, 밀리의서재) 옆에 두면 아직 미완성이다.
3. 답을 열기 전 질문 화면의 아래 절반이 비고, 머리 마크가 메뉴 아이콘으로 읽혀, 처음 쓰는 사람이 덜 만든 페이지나 눌리지 않는 메뉴를 만난다.

## 6. 실서비스에는 있는데 이 설계에 빠진 것

상태와 엣지 케이스
- 누름·초점·끈 상태 화면: 34장 모두 기본 상태뿐이다. 카드 누름(`scale(.97)`), 주 버튼 누름(`brightness(.92)`), 키보드 초점 테두리, 꺼진 주 버튼(`--cta-off`) 을 한 장씩.
- 질문 화면과 시뮬레이션 목록의 불러오는 중: 홈만 자리 모양(loading.png)이 있다. 포스터 30장이 그려지기 전 빈 연한 파랑 칸이 어떻게 보이는지.
- 글자 키움: iOS 텍스트 크기 최대, 브라우저 200% 에서 히어로, 탑 이름, 하단 막대 세 버튼(`헷갈려요` 가 한 줄로 남는지).
- 데스크톱 폭: 4절에 규칙은 있지만 장면 스크린샷이 없다(최대 폭 가운데 정렬과 양옆 바탕).
- 알림 한 줄이 하단 막대 위에 뜨는 질문 화면 장면(지금은 홈에서만, 막대가 없는 상태로 찍힘).
- 실기기 틀: 노치·홈 표시줄 안전 영역이 들어간 상태로 찍은 장면이 없다. 하단 막대 아래 여백을 눈으로 확인할 수 없다.

디테일
- 시트 손잡이와 바탕 눌러 닫기 표시(resetSheet 에 손잡이가 없음. 토스 계열은 있음).
- 포스터 그림의 대체 이름: 포스터는 `aria-hidden` 이라 괜찮지만, 시뮬레이션 카드 이름이 두 줄로 끊길 때 슬래시 앞뒤 줄바꿈(`끼우기/` 다음 줄 `빼기`)을 막는 처리(`/` 뒤 `<wbr>` 위치 또는 `keep-all` 예외).
- 히어로 그림 띠의 과목별 차이: 장면 그림이 바뀌어도 띠 바탕은 늘 같은 `--stage` 라, 과목이 바뀐 것을 그림으로만 안다. 실서비스는 과목 표지에 작은 변화(사물 배치, 따뜻한 색 위치)를 고정 규칙으로 둔다.

문구 톤
- 시뮬레이션 머리 분류 줄 `TCP/IP · 관련 질문 1`: 주제와 개수가 한 줄에 붙어 뜻이 모호하다. `관련 질문 1개` 처럼 단위를 붙이거나 개수를 아래 관련 질문 섹션에만 둔다.
- 시뮬레이션 마지막 버튼 `글로 정리하기`: 사용자가 정리 글을 쓰는 동작으로 읽힐 수 있다. 실제 동작은 관련 질문으로 가기라 `질문으로 돌아가기` 또는 `글로 읽기` 가 정확하다.

### 1. AI 티 없음, 개성 (18.5 / 20)

- 좋은 점: 앱 아이콘, 히어로 진행 칸, 과목 탑, 목차 장 머리 블록 줄, 끝 영역 블록 줄이 한 부품이고, 헷갈림은 빨간 테두리, 읽는 중은 반 칸으로 한 줄 안에 상태가 다 읽힌다(`homeMid`, `toc`, `qEndWait`). `homeDone` 의 꽉 찬 파란 탑 + 배지가 이제 `40문항을 모두 쌓았어요` 와 같은 말을 한다. 기준선 p-flow 와 나란히 두면 v2 가 분명히 운영 중인 서비스 쪽이다.
- 히어로 그림이 아이콘 세트 수준 (-1). `hero-os`, `hero-net`, `hero-db` 는 다시 그려 결이 고르지만 칩, 모니터와 편지, 원통과 표라는 흔한 조합이다. 토스 계열 히어로처럼 이 앱만의 장면은 아니다. 시각 평가자 영역이라 감점은 지난 회차와 같게 둔다.
- 상태 그림의 뜻이 조금 어긋남 (-0.5). `loadFail`, `qFail` 은 문서 + 돋보기(찾는 중, 없음의 뜻)인데 글은 `인터넷 연결을 확인하고 다시 시도해 주세요` 다. 그림은 `notFound`(`찾는 질문이 없어요`)와 똑같아 세 가지 다른 실패가 한 그림이다. `ill-empty-conf` 위의 주황 점은 카드 위 머리처럼 보여 사람 + 체크(본인 확인) 아이콘으로 읽힌다. 둘 다 글이 뜻을 바로잡아 작다.

### 2. 정보 구조와 화면 흐름 (14.5 / 15)

- 좋은 점: 들어온 길마다 위치 글, 막대, 답 상태, 켜진 탭이 다르고 화면에서 바로 읽힌다(`q` `9개 중 5번째`, `qConf` `헷갈림 3개 중 2번째`, `qLong` `빈출 20개 중 18번째`, `random` 은 위치 글 없음 + 홈 탭). 복습 행 → 목차 헷갈림만 → 첫 문항 → 뒤로까지 실제로 끊기는 곳이 없다. `qConfLast` 의 `목록으로`, `qSubEnd` 의 과목 경계 안내, `confEmpty` 와 `confCleared` 의 다른 문구(`읽다가 헷갈리면 질문 아래 헷갈려요를 눌러 두세요` / `다시 볼 질문이 생기면 여기에 모여요`)가 다음 행동을 알려 준다. 홈 섹션이 features.md 홈 목록(이어 읽기, 랜덤, 과목 진도, 빈출, 시뮬레이션)과 정확히 맞고 넘치는 것이 없다.
- 자동 쌓임 순간 손가락 밑 버튼이 반대 뜻으로 바뀜 (-0.25). 실측: 기다리는 중 `읽음으로 표시` 상자는 가로 290~370, 세로 679~723이고, 시간이 차서 자동으로 쌓이면 같은 자리에 `읽음 취소`(315~370, 682~726)가 나온다. 끝 영역을 보다가 `읽음으로 표시` 를 누르려는 바로 그 순간 시간이 차면, 사용자는 방금 쌓인 것을 취소하게 된다. 드물지만 한 번 겪으면 무엇이 일어났는지 알 수 없는 종류다.
- 높이 700 미만 시뮬레이션의 글 입구 (-0.25). 지난 회차와 같다. 중간 단계에서 질문 글로 가는 길은 직접 해 보기 폼 아래 `관련 질문` 까지 내리는 것뿐이다. 844 높이에서는 한 번 내리면 닿아 감점을 줄였다.

### 3. 모바일 가독성 (14 / 15)

- 좋은 점: 본문 17/30, 첫 문장 형광펜(`qa`, `randomOpen`), 102자 제목도 375 x 667 과 360 폭에서 답 보기까지 첫 화면(`qLong`). 글자 200% 질문은 머리 두 줄, 막대 두 줄(`[←][헷갈려요]` / `[다음 질문]`)로 아무것도 잘리지 않고 막대가 화면의 28%다(실측). 가로 모드 답 보기가 첫 화면 안(`landscape-q`). 노치·홈 표시줄(`safe-*`) 맞음.
- 글자 200% 에서 목차와 시뮬레이션 목록이 깨짐 (-1). 제출된 `shots/extra/zoom200-*` 는 home, q, qa, sim, simLast 만 있다. 같은 조건(195 x 422)으로 목차를 열면:

  - 분할 선택 `헷갈림만 3` 이 세 줄(`헷갈 / 림만 / 3`)이 되어 내용 높이 54 가 칸 높이 44 를 넘는다.
  - 장 이동 줄 너비 319 중 195만 보이고 `데이터베이스`, `네트워크` 가 화면 밖인데 가장자리 흐림이나 화살표가 없다(가로 스크롤 표시 없음).

### 4. 모션 (9.75 / 10)

- 좋은 점: 영상 4개 모두 6초 이하, 바뀐 것만 움직인다. `answer-reveal` 은 이제 판이 흐려진 뒤 본문이 올라와 한 프레임에 사라지지 않는다. `sim-step` 은 새 화살표 하나와 설명 글만 바뀐다. 위 자리 알림은 위에서 8 내려와 결과 숫자를 덮지 않는다.
- 동작 있는 알림이 엄지에서 멂 (-0.25). 초기화 되돌리기 버튼은 위 105~149(실측), 읽음 취소 되돌리기는 위 72~118 이다. 사용자는 방금 화면 아래(시트의 `초기화` 820 근처, 끝 영역의 `읽음 취소` 682 근처)를 눌렀고, 되돌릴 손은 아래에 있다. 6.1인치 폰을 한 손으로 쥐면 맨 위는 가장 닿기 어려운 자리다. 특히 읽음 취소 알림의 `되돌리기` 는 손가락 바로 밑의 `읽음으로 표시` 와 같은 일을 하므로 위에 따로 띄울 이유가 약하다.

### 5. 시스템 일관성 (9.75 / 10)

- 좋은 점: 분수는 읽은 수, 위치는 `N개 중 k번째` 하나의 규칙. 주 버튼은 상태마다 하나(답 가림이면 `답 보기`, 펼치면 `다음 질문`). 꺼진 이전 버튼이 이제 바탕 그대로 + 흐린 아이콘이라 눌린 것처럼 보이지 않는다(`qTip`, `qFirstRead`, `simTry`). 직접 해 보기 오류가 05 표의 모양과 같아졌다. 끝 영역 문구가 `쌓였어요 / 읽은 질문이에요 / 아직 쌓이지 않았어요` 로 한 비유 안에 있다.
- 200% 에서 블록이 점으로 변함 (-0.25). 목차 장 머리 블록 줄과 끝 영역 블록 줄이 200% 에서 폭 8 이하가 되어 동그란 점(`●●●◐○○`)으로 그려진다(`sheets/z3.png`). 진행 칸은 12 미만이면 이어진 막대로 바꾼다는 규칙(00 5.6)이 있는데 블록에는 그런 규칙이 없어, 앱의 상징인 블록이 설계되지 않은 모양이 된다.

### 6. 구현 가능성 (9 / 10)

- 좋은 점: 48장면 x 390 / 360 에서 44 x 44 미만 누르는 것 0개(알림 버튼 포함, 내 측정). 시트 `role=dialog` + `aria-modal` + 열면 제목 초점 + 취소 시 연 버튼으로 초점 복귀. 알림 `role=status`, 초기화 되돌리기 10초와 누르거나 초점이 있는 동안 멈춤. 직접 해 보기 `aria-invalid` + `aria-describedby` + `role=alert`. 질문·시뮬레이션 화면은 열면 제목(h1)에 초점(실측). 가로 모드, 안전 영역, 움직임 줄이기까지 다룬다.
- 주 탭 세 화면에 제목이 없어 초점이 문서 처음에 머묾 (-0.5). 00 7.4 는 `화면이 바뀌면 새 화면의 제목(h1, tabindex=-1)에 초점. 뒤로 왔을 때는 들어갈 때 누른 행이나 카드에 초점`, 10절은 `화면 읽기 프로그램에는 새 화면 제목이 먼저 읽힌다` 고 한다. 실측: 홈, 목차, 시뮬레이션 목록에는 h1 이 없고, 홈 → 목차 탭, 복습 행 → 목차, 질문 → 뒤로 목차 모두 `document.activeElement` 가 BODY 다. 화면 읽기 사용자는 화면이 바뀐 것을 듣지 못하고, 질문에서 뒤로 오면 누른 행이 아니라 맨 위에서 다시 시작한다.
- 제자리 동작 뒤 초점을 잃음 (-0.25). `읽음으로 표시`, `읽음 취소`, 초기화 뒤 모두 초점이 BODY 로 간다(끝 영역을 통째로 다시 그려 누른 버튼이 사라짐). 키보드 사용자는 다음 Tab 이 문서 처음부터 시작한다. `한 칸 쌓였어요` 는 알림이 아니라 끝 영역 글이 바뀌는 것이라 화면 읽기에 읽히지도 않는다.
- 검사가 200% 목차를 못 봄 (-0.25). verify.py 는 가로 넘침만 세고, 200% 증거 사진에 목차와 시뮬레이션 목록이 없어 3절의 깨짐이 통과로 남았다.

### 7. 레퍼런스 도입 (9.5 / 10)

- 좋은 점: AnkiMobile 의 복습 숫자가 홈 첫 스크롤 안 `헷갈림 3문항 다시 보기` 로 있고, Apple Books 의 `다 읽음으로 표시` 와 같은 손 표시가 `읽음으로 표시` 로 들어왔다. 토스 TDS 목록 행, Reader 계열 끝 영역이 근거 있는 것만 남았다.
- 바로 시작이 아님 (-0.5). 지난 회차와 같다. 행 → 목록 → `첫 문항부터 다시 읽기` 로 두 번 누른다. 무엇이 남았는지 확인시키는 이유가 있어 수용 가능하지만, 3분 세션에서는 한 번이 아깝다.

### 8. 사용자 목적 부합 (9.5 / 10)

- 좋은 점: 답 가림이 홈, 목차, 빈출, 랜덤 카드, 질문 어디서도 깨지지 않는다. 이미 읽은 질문도 가림으로 열려 다시 떠올리기가 복습이 된다. 읽기 → 헷갈림 표시 → 홈 복습 행 → 다시 보기 고리가 닫혔고, 이제 빨리 훑은 사용자도 `읽음으로 표시` 로 쌓을 수 있다. 면접 연출 없음, 기능 범위가 features.md 와 맞다.
- 읽음 취소 뒤 규칙이 빔 (-0.5). 실측: `읽음 취소` 를 누르면 끝 영역이 `아직 쌓이지 않았어요` + `읽음으로 표시` 로 바뀐다. 사용자가 직접 취소했는데 `아직` 이라고 하면 잠시 뒤 저절로 다시 쌓일 것처럼 읽힌다. 03 5.6 은 `읽음 취소를 누름: 글이 빠지고` 라고 적어 시안과 문서가 다르다. 더 큰 문제는 규칙 공백이다. 6.3 은 `자동 판정은 그대로` 라고만 하는데, 취소하는 순간 이미 끝 영역이 보이고 답을 연 지 시간이 지났으므로 그대로 구현하면 취소가 곧바로 자동 판정에 덮인다. 시안에서는 관찰자가 옛 끝 영역에 걸려 있어 우연히 다시 쌓이지 않을 뿐이다(20초 대기 실측, 다시 안 쌓임).

점수는 통과선 위이고 판정도 예다. 아래 필수는 판정을 뒤집지는 않지만 자기 문서의 약속을 어기는 것이라 앱에 넣기 전에 고친다. 셋 다 작다.

### 필수

1. **글자 200% 목차·시뮬레이션 목록을 접는다** (02 장 머리, 04 장 머리, 00 5.7 분할 선택, 장 이동 줄, 10절, verify.py)

## 실서비스 판정: 예

1. 시뮬레이션 가림을 뺀 범위에서 흐름, 숫자 규칙, 복습 입구, 읽음 판정, 상태 화면, 누르는 영역이 앱스토어 상위 학습 앱과 토스 계열 화면 옆에 두어도 밀리지 않는다. 3회차 판정을 아니오로 만든 이유(가림과 그 검사)는 사용자 결정으로 이번 판단에서 빠졌다.
2. 남은 결함(200% 목차 깨짐, 읽음 취소 뒤 규칙, 주 탭 초점)은 실서비스에서도 출시 뒤 고치는 P2 수준이고, 셋 다 문서 몇 줄과 작은 CSS 로 고쳐진다. 핵심 공부 흐름을 막는 것은 없다.
3. 다만 필수 1~3 은 자기 문서(00 7.4, 10절, 03 5.6)의 약속과 다른 것이라, 앱에 옮길 때 같이 고쳐야 예가 유지된다. 통과 뒤 시뮬레이션 가림 점검에서 3회차 수준의 결함이 다시 나오면 이 판정은 다시 본다.

## 실서비스에는 있는데 이 설계에 빠진 것

상태
- 읽음 취소 뒤 상태: 자동 판정이 다시 켜지는지, 끝 영역에 무엇을 보이는지(필수 2).
- 자동 쌓임이 버튼을 바꾸는 순간의 오누름 방지(권장 4).
- 제자리 동작 결과의 화면 읽기 알림: `한 칸 쌓였어요` 가 화면 읽기에 읽히지 않는다(필수 3).

엣지 케이스
- 글자 200% 목차·시뮬레이션 목록: 장 머리 한 글자씩 세로, 분할 칸 넘침, 장 이동 줄 잘림 표시 없음(필수 1).
- 글자 200% 블록 줄이 점으로 변함(권장 6).
- 오프라인일 때 못 불러옴 장면이 캔버스에 없다. 그 경우 쓰는 `ill-offline` 은 여전히 구름 + 아래 화살표라 내려받기로 읽힌다(장면이 없어 감점 없음).
- 글자 200% 시뮬레이션 무대 옆 잘림(가림 범위라 통과 뒤 점검 때).

문구 톤
- `아직 쌓이지 않았어요` 가 이유와 시점을 말하지 않고, 읽음 취소 뒤에도 같은 말이 나온다.

- `처음부터 5단락`, `6단락 중 3번째` 의 `단락` 은 본문 문단 수와 맞지 않아 보이는 문제가 남았다(작음).

디테일
- 동작 있는 알림(되돌리기)이 화면 맨 위, 방금 누른 손에서 가장 먼 자리.
- 주 탭 화면에 제목 h1 이 없어 뒤로 왔을 때 누른 행으로 돌아가지 않는다.
- `ill-empty-conf` 의 주황 점이 사람 머리처럼 보임.

### 1-1. AI 티 없음, 개성 (16/20)

좋은 점: 과목 탑과 블록 줄은 여전히 이 앱만의 그림이고, 이번에 들어온 PNG 는 사용자가 좋아하는 오픽 일러스트(파랑 면, 흰 면, 따뜻한 점 하나)와 같은 집안이다. 히어로가 가운데로 오고 마크가 사라져 홈 첫 화면이 깨끗해졌다.

감점 사유
- **다 읽음 그림이 덜 쌓인 탑이다(-1).** `hero-done.png` 는 2열 6줄인데 줄 색이 위에서부터 파랑, 흰색, 연파랑, 파랑, 흰색, 파랑이다. 이 앱에서 흰 칸은 안 읽음, 연파랑은 읽는 중이다(00 5.5). 그래서 homeDone 의 `40문항을 모두 쌓았어요` 위에 빈 칸이 섞인 탑이 서고, 바로 아래 과목 진도의 진짜 탑(전부 파랑)과 말이 어긋난다. 맨 위 따뜻한 색 면은 프롬프트의 `round badge` 가 아니라 맨 윗줄 뒤에 반쯤 가려진 막대라 잘린 실수처럼 보이고, 체크는 파랑 블록 위에 있다. 줄 사이 틈도 없어 앱 블록(틈 2)과 모양이 다르다. 알파 영역은 1050 중 215(20%)라 띠 안에서 혼자 좁다.
- **그림 소재가 CS 아이콘 팩 그대로다(-1).** 칩, 원통, 지구본, 모니터와 서버 상자는 1회차부터 지적된 가장 흔한 소재이고, PNG 로 만들어도 결이 머티리얼 아이콘이다. 오픽 그림(커피잔과 케이크, 해 뜨는 진행 막대)은 사물에 장면이 있는데 여기 장면 4장은 기호 두 개를 나란히 둔 것에 가깝다. 기호는 실루엣 구분이 먼저라는 결정(illustrations.md 0-1)은 존중하되, 장면까지 아이콘 나열인 점은 감점한다.
- **상태 그림 2장이 뜻을 틀리게 말한다(-0.5).** `ill-empty-conf.png`(confEmpty, confCleared)는 흰 타원 윗면 + 둥근 아랫면 원통이라 `sym-db`, `hero-db` 와 같은 실루엣이다. 목차 헷갈림만 0개 화면에 데이터베이스 기호가 체크를 달고 서 있다. 처음 온 사람이 헷갈림만을 누르면 가장 먼저 보는 빈 화면이다. `ill-offline.png` 는 구름 + 아래 화살표라 내려받기 아이콘이고, loadFail, qFail 의 `불러오지 못했어요` 와 반대 뜻으로 읽힌다. 옆 문서 귀퉁이의 작은 주황 점은 뜻 없는 얼룩이다.
- **시뮬레이션 목록은 여전히 도식 견본판이다(-1).** 방식은 확정이라 두지만, 30칸이 같은 연파랑 판 위 남색 도식이고 칸 안 글자는 6~8px 잔무늬다. 2회차 지적 그대로 남는다.
- **카드 3단 리듬 반복(-0.5).** 히어로, 랜덤, 질문 머리, 시뮬레이션 머리가 모두 `파랑 분류 줄 / 굵은 제목 / 회색 메타`. 위계는 고쳐졌지만 같은 틀 반복은 그대로다.

### 1-3. 모바일 가독성 (12.5/15)

감점 사유
- **글자 200% 에서 질문 머리 탭이 부딪히고 잘린다(-1).** zoom200-q, zoom200-qa 에서 작은 탭 줄이 `목차시뮬레이` 로 붙어 보이고 마지막 글자가 반쯤 잘린다. CSS 는 `@container (max-width: 339px)` 에서 `.stabs { overflow-x: auto }` 로 옆으로 밀게 했지만(398~400행 근처), 가장자리 흐림도 틈도 없어 넘침 버그로 읽힌다. 같은 화면 하단 막대는 `헷갈려요` 글을 지우고 물음표 아이콘만 남긴다(388행). 물음표 하나는 도움말로 읽힌다.
- **포스터 잔글씨(-1).** 2회차와 같다. posters-360 에서 `용량 4 · 원소 4개`, `40보다 작은 값`, `삽입 전` 같은 글이 6~8px.
- **줄바꿈 고아(-0.5).** 360 qConf 위 줄 `Hash table & BST(Binary Search` 다음 줄에 `Tree)` 혼자. qTip 안내 두 줄이 가운데 정렬에 `열어 보세요.` 만 남음. qSubEnd 표의 `테이블 안의 다른` 다음 줄 `칸`, `tombstone` 다음 줄 `필요`.

### 1-4. 모션 (9/10)

영상으로 본 것

- 탑 쌓기: 0.5초 무렵 섹션이 반쯤 보일 때 아래 줄부터 흐림에서 진하게 올라오고 0.9초 무렵 끝난다. 탑마다 높이가 다르게 멈추는 것이 데이터 그대로라 의미가 선다. 다만 녹화가 부드러운 스크롤 도중이라 줄마다 24ms 간격(9.1 stagger)이 실제로 보이는지는 판정이 어렵다.
- 시뮬레이션 단계: 새 메시지와 상태 글이 약 200ms 에 나타나고 앞 메시지는 회색으로 물러난다. 단계 칸이 차고 설명이 바뀐다. 지금 바뀐 것만 진하게 남는 규칙이 잘 보인다.

- **PNG 파랑이 토큰보다 어둡고 그림자가 들어갔다(-0.5).** 12장 주된 파랑이 #5080F0 부근, `hero-net.png` 는 #4078E8 부근으로 토큰 #6194F8 보다 한 단계 어둡다. `sym-ds.png` 바깥 칸은 #A8C0F0 으로 팔레트에 없는 색이다. `hero-os`, `hero-db` 의 흰 카드에는 부드러운 그림자가 있다(공통 프롬프트 `no shadows`).
- **기호 4개의 시각 무게가 다르다(-0.5).** `sym-ds.png` 알파 영역은 326 x 117(가로로 납작), 나머지 셋은 약 270 x 265. 홈 탑 이름 줄, 목차 장 머리, 시뮬레이션 목록 장 머리, 떠올리기 판에서 자료구조만 반 크기에 옅은 색이라 비어 보인다. 장면도 같아서 `hero-ds.png` 는 높이 360 중 122(34%), `hero-db`, `hero-os` 는 274(76%)라 과목이 바뀌면 히어로 띠의 무게가 반으로 줄었다 늘었다 한다.

### 1-6. 구현 가능성 (8.5/10)

좋은 점: 안전 영역(safe-*), 넓은 화면(wide-home 가운데 430), 가로 모드, 200% 장면을 모두 찍어 둔 것은 실서비스 문서 수준이다. 부품 상태 줄(누름, 초점 2px, 꺼짐)도 캔버스에 있다.

감점 사유
- **200% 증거 사진에 버그가 그대로 있다(-1).** 1-3 첫 항목의 탭 충돌에 더해, zoom200-sim 에서 하단 막대가 y 635 부터 1688 까지 화면의 62% 를 덮어 무대가 거의 안 보인다. 찍어 두고 판정하지 않았다.
- **가로 모드 질문에서 주 동작이 막대 밑에 반쯤 숨는다(-0.5).** landscape-q 의 `답 보기` 가 하단 막대에 반쯤 가려진다. 높이 700 미만 규칙(03 0절)이 기호만 빼고 판 아래 버튼 위치는 그대로 둔 결과다.

### 1-7. 레퍼런스 도입 (9/10)

히어로 그림이 띠 가운데를 채워 브릴리언트 이어 하기 카드 구성이 제대로 옮겨졌다. 오픽 일러스트 결과도 맞는다. 감점: 화면 정체성의 대부분이 여전히 토스 TDS(회색 띠, 분할 선택, ListRow, 하단 막대)에서 온다(-1). 탑과 블록 줄이 그 위에 얹힌 이 앱 것이다.

### 1-8. 사용자 목적 부합 (9/10)

질문 화면은 리더, 목차는 교재 목차, 시뮬레이션은 단계 학습으로 공부 자료 결이 선다. 1차 범위 밖 기능은 없다. 감점: 시뮬레이션 목록이 학습 입구보다 기술 문서 썸네일 모음으로 보여 무엇부터 누를지 고르기 어렵다(-0.5). 다 읽음 그림이 성취를 덜 쌓인 탑으로 보여 준다(-0.5).

## 2. 총점

**85 / 100** (통과 기준 90 미달)

## 3. 고쳐야 할 것

### 필수 (90점과 실서비스 판정에 필요, 우선순위 순)

1. **다 읽음 그림을 꽉 찬 탑으로(`illustrations/hero-done.png`, `ready.js`).** 가장 싼 길: `ILL_READY` 에서 `hero-done` 을 빼 illustrations.md 4.1 대체 그림(데이터대로 과목 탑 4개가 꽉 참, 공유 이미지와 같은 그림)이 나오게 한다. 이 앱 블록 그대로라 문법이 어긋날 수 없다. PNG 를 지키려면 다시 뽑는다: `every block the same blue #6194F8, a 2px gap between rows, no white or pale blocks, one round warm badge with a navy check fully visible above the top row`. 어느 쪽이든 homeDone 을 다시 찍어 바로 아래 과목 진도 탑과 나란히 본다.
2. **헷갈림 0개 그림이 데이터베이스로 읽히지 않게(`ill-empty-conf.png`).** 원통 실루엣(타원 윗면, 둥근 아랫면)을 버리고 앱 블록 그대로: 납작한 둥근 막대 4개, 막대 사이 틈, 맨 위 위로 둥근 따뜻한 배지 + 남색 체크. 다시 뽑을 때 `flat rounded bars with square ends, visible gaps between bars, no ellipse, not a cylinder` 를 넣고, 48 크기에서 `sym-db` 옆에 놓아 실루엣이 다른지 본다.
3. **불러오기 실패 그림에서 다운로드 뜻을 뺀다(`ill-offline.png`).** 아래 화살표를 지우고 구름 + 짧은 가로 줄(끊김) 또는 구름과 문서 사이 끊긴 점선으로. 주황 점은 지운다. loadFail, qFail 두 장을 다시 찍는다.
4. **글자 200% 머리와 막대(00 10절, `index.html` 388~400행).** (a) 좁은 열에서는 작은 탭 줄을 숨기고 뒤로 + 지금 위치 이름만 둔다(`.stabs { display: none }`, 탭 이동은 뒤로와 홈에서). 옆으로 미는 줄을 남기려면 오른쪽 끝 24px 흐림(`mask-image: linear-gradient(90deg, #000 85%, transparent)`)과 탭 사이 16 을 둔다. (b) `헷갈려요` 는 글을 지우지 말고 막대를 두 줄(`[←][헷갈려요]` / `[다음 질문]`)로. (c) 시뮬레이션 막대는 단계 설명을 2줄로 자르고(`line-clamp: 2`, 누르면 펼침) 막대 높이가 화면의 40% 를 넘지 않게. zoom200 4장을 다시 찍어 판정 결과를 14절에 적는다.
5. **자료구조 기호와 장면의 무게를 맞춘다(`sym-ds.png`, `hero-ds.png`).** 기호는 프롬프트대로 칸 3개 모두 #6194F8, 가운데만 #03257B 로 위로, 정사각 틀의 높이 45% 이상. 장면은 칸 높이를 키워 알파 영역 높이가 다른 장면처럼 360 중 250 안팎이 되게. 홈 탑 이름 줄과 목차·시뮬레이션 장 머리를 다시 찍어 네 기호가 같은 크기로 읽히는지 본다.
6. **답 펼침에서 판을 흐려 보낸다(00 9.1, `index.html` 1198행).** 다시 그리기 전에 `.recall` 에 `opacity 0` 을 `fade`(120ms, standard)로 주고 `transitionend` 뒤에 본문을 `base` 로 올린다. `motion/record.py` 로 다시 찍어 25fps 에서 판이 흐려지는 프레임이 3장 이상인지 본다.
7. **입력 오류 상태(05, simErr).** 잘못 넣은 칸에 1.5px 오류 테두리와 `aria-invalid="true"`, 안내 글은 오류 글자색(흰 바탕 대비 4.5 이상인 빨강 토큰)으로. 앱의 빨강 하나를 쓰고 새 색은 만들지 않는다.

### 권장

- PNG 색을 팔레트로 고정: 12장을 #6194F8, #03257B, #EAF1FE, #FFFFFF, #FFE0B0 다섯 색에 가장 가까운 색으로 바꾸는 작은 PIL 스크립트 한 번(가장자리 반투명은 알파 유지). `hero-os`, `hero-db` 카드 그림자는 지운다.
- 질문 불러오는 중 자리 모양을 판 하나 대신 본문 줄 6개(폭 100, 92, 96, 60% 반복)로. 그러면 떠올리기 판과 실루엣이 갈린다.
- 겹친 판 모서리: 안쪽 = 바깥 - 간격(16 - 8 = 8)으로 맞추거나 안쪽 판을 빼고 바깥 판 하나로(homeEnd, qFig).
- 시뮬레이션 메시지: 이름표가 보내는 쪽 줄에서 받는 쪽으로 `translateX` 240ms `out` 으로 간 뒤 멈춤. transform 만이라 9.2-1 규칙 안이다.
- 가로 모드 질문: 높이 500 미만에서는 `답 보기` 를 판 안이 아니라 판 위(제목 바로 아래)로.
- 줄바꿈: 괄호 묶음 `(Binary Search Tree)` 는 `white-space: nowrap`, 가운데 정렬 안내 글에는 `text-wrap: balance`.
- 분할 선택 글 굵기는 조각이 절반쯤 왔을 때(약 80ms 뒤) 바꾼다.
- 오류·빈 화면(loadFail, qFail, notFound, confEmpty)은 그림 + 글 + 버튼 묶음을 남은 높이의 위 3분의 1 지점에 두어 아래 55% 가 비지 않게.
- 탑 쌓기 녹화는 스크롤 없이 탑이 보이는 위치에서 시작해 줄마다 간격이 보이게 다시 찍는다.

## 4. 좋은 점 (짧게)

- 2회차 손질 결함(조각 찌그러짐, 포스터 반쪽 글자, 빈 아래 절반, 메뉴 같은 마크, 납작한 위계, 고아 꼬리표, 행 빈 띠)이 화면에서 모두 사라졌다.
- 홈 첫 화면이 그림 띠, 이어 읽기, 랜덤, 탑으로 위에서 아래로 한 번에 읽히고, 지금 앱(회색 바탕 위 흰 상자 더미) 대비 확실히 운영 중인 서비스 결이다.
- 질문 읽기 화면(qa, resume, qEnd, qSubEnd)은 글자, 코드 판, 표, 꼬리질문 펼침, 끝 영역 블록까지 리더 앱 수준이다.
- 상태 장면이 47장으로 실서비스 수준의 폭을 덮는다(불러오는 중 3종, 실패 3종, 저장 안 됨, 저장값 깨짐, 새 판, 되돌리기, 첫 알림).
- 분할 선택과 시뮬레이션 단계 모션은 바뀐 것만, 짧게, 의미대로 움직인다.

## 5. 실서비스 판정: 아니오

1. 다 읽음 화면(이 앱의 가장 큰 보상 순간)의 그림이 이 앱 블록 문법으로 덜 쌓인 탑이고 장식 면이 잘려 있다. 운영 서비스라면 출시 전 이미지 검수에서 걸린다.
2. 헷갈림 0개(새 사용자가 자주 만나는 빈 화면)에 데이터베이스 기호가, 불러오기 실패에 다운로드 아이콘이 나온다. 그림이 문구와 다른 말을 한다.
3. 글자 200% 증거 사진에서 머리 탭이 부딪혀 잘리고 막대가 화면의 62% 를 덮는다. 찍어 놓고 판정하지 않은 상태로는 접근성 검수를 통과하지 못한다.

필수 1~4 를 고치면 판정은 예로 본다. 1~7 을 다 고치면 시각 렌즈 점수는 90~92 범위다.

## 6. 실서비스에는 있는데 이 설계에 빠진 것

상태와 엣지 케이스
- 일러스트 검수 기록: 오픽 final 에는 `image-review.md` 가 있다. 이 v2 는 12장을 넣었지만 장마다 프롬프트 지킴(색, 그림자, 구도), 뜻 맞음(문구와 같은 말인지), 같은 크기에서의 무게를 적은 검수표가 없다. 위 필수 1~3, 5 가 모두 이 검수 한 번이면 잡힌다.
- 입력 오류 색과 테두리(simErr), 입력 초점 테두리 장면.
- 알림 두 개가 겹칠 때(예: 오프라인 저장 끝 알림이 떠 있는 동안 되돌리기 알림) 무엇이 이기는지.
- 글자 200% 판정 결과: 사진은 있는데 통과·실패 판정과 고칠 목록이 14절에 없다.

디테일
- PNG 가장자리 결: `hero-ds` 칸끼리 반투명하게 겹친 경계, 카드 그림자처럼 생성 모델 흔적이 남은 곳을 손으로 지운 버전.
- 과목 히어로 4장의 같은 높이 규칙(알파 영역 높이 기준값)과 기호 4장의 같은 무게 규칙.
- 겹친 판 모서리 규칙(안쪽 = 바깥 - 간격)을 00 모서리 절에 한 줄로.

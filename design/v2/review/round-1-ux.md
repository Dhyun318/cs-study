# 라운드 1 평가: UX 리서처 / 정보 구조 관점

평가자 관점: 학습 제품의 공부 흐름, 재방문, 이동, 인지 부하, 접근성, 출퇴근길 실제 모바일 사용(한 손, 짧은 세션, 사파리 툴바, 끊기는 네트워크).
대상: `design/v2/spec/00~06`, `design/v2/illustrations.md`. 맥락: `docs/features.md`, `design/CLAUDE.md`, `design/references-rea.md`, 현재 앱 스크린샷(after-390-*), 오픽 flow.png.
사실 확인을 위해 읽기 전용으로 더 본 것: `app/data/notes.json`(문항 길이, 소제목, 별 개수 집계), `app/app.js`(본문 불러오기), `app/CLAUDE.md`(현재 이동 규칙), `sims/_kit/kit.css`.

## 총점: 70 / 100 (통과 기준 90 미달, 실서비스 판정 아니오)

화면 하나하나의 생김새와 토큰은 꼼꼼하다. 하지만 화면 사이를 오가는 규칙(어디서 들어왔나, 뒤로 가면 어디로 가나, 무엇이 이어 읽기 대상인가)과 실제 휴대폰 조건(사파리 툴바, 작은 화면, 긴 제목)이 설계되어 있지 않다. 공부 흐름의 핵심인 답 가리기도 지금 설계로는 답을 미리 보여 준다.

### 1. AI 티 없음, 개성 (15 / 20)

- 좋은 점: 앱 이름 차곡과 진도 블록이 같은 은유(00-system 3절 원칙 2, 6.4)라 브랜드가 곧 데이터 표현이다. 이건 남이 흉내 내기 어려운 고유 부품이다.
- 감점 (-2): 01-home 1절이 섹션마다 모양을 일부러 다르게(그림판, 카드 뭉치, 블록 탑, 카드 띠, 무대) 정했다. 다르게 만든 이유가 내용이 아니라 단조로움 회피라서, 실제로는 한 화면에 위젯 5종을 늘어놓은 쇼케이스가 된다. 토스 홈이나 밀리의서재 홈은 모양 종류가 2~3개다.
- 감점 (-2): 기울어진 카드 3장 뭉치(01-home 4.3, rotate -2.2/1.8deg)와 손가락 따라 기우는 밀기는 드리블 시안에서 흔한 연출이다. 밀기 방향에 의미가 없어서(아래 2절) 손맛만 남는다.
- 감점 (-1): 정체성의 절반을 맡는 과목 그림 4장(illustrations.md)이 아직 없다. 대체 SVG 묘사(둥근 칸 4개, 칩과 핀, 원통)는 평범한 아이콘 수준이라, 그림이 안 나오면 P 의 아이콘 원으로 돌아간다.

### 2. 정보 구조와 화면 흐름 (8 / 15)

가장 크게 깎았다. 화면 안은 자세한데 화면 사이 규칙이 비어 있다.

- 진입 맥락이 정의되지 않음 (-2). 02-toc 7절은 목차에서 들어온 경우만 이전/다음 순서와 위치 글(`5 / 9`, `빈출 4 / 20`)을 정한다. 홈 히어로, 랜덤 카드, 빈출 카드 띠, 시뮬레이션 관련 질문, 글로 정리하기로 들어온 질문의 이전/다음 순서, 위치 글, 뒤로 목적지가 어디에도 없다. 홈에서 들어오는 길이 다섯 개인데 전부 미정이다.
- 기록(뒤로) 규칙이 현재 앱 결정과 반대 (-1). 02-toc 7절은 칩을 바꾸면 주소가 바뀌어 뒤로가 칩 단위로 동작한다고 했다. `app/CLAUDE.md` 구조 결정은 목차 칩과 이전/다음이 기록을 쌓지 않는다. 칩 단위 기록이면 칩을 세 번 바꾼 사용자는 목차를 나가려고 뒤로를 세 번 눌러야 한다. 이전/다음이 기록을 쌓는지는 03-question 에 아예 없다. 다음을 10번 누른 뒤 뒤로를 누르면 목록의 어느 행으로 돌아오는지(처음 누른 행인지 지금 질문 행인지)도 없다.
- 이어 읽기 대상이 덮어써짐 (-1). 03-question 3절은 멈춘 곳을 화면을 떠날 때마다 저장한다. 그러면 랜덤 카드로 질문을 잠깐 열었다 닫기만 해도 홈 히어로가 그 질문(0 / N)으로 바뀌고, 길게 읽던 질문은 사라진다. 또 답을 펼치지 않고 떠난 질문을 이어 읽기로 열면 06 6절 규칙대로 답 펼친 채로 열려 떠올리기 기회가 없어진다.
- 진도 상태 모델이 없음 (-1). 읽음, 읽는 중, 안 읽음과 헷갈림이 겹칠 수 있는지, `10 / 12` 에 헷갈림이 켜진 읽은 질문이 들어가는지, 탑에서 읽음+헷갈림 질문이 어떤 블록으로 그려지는지(00-system 6.4 는 상태를 하나만 고르게 그림) 정의가 없다. 목차의 읽는 중 40% 글리프는 질문마다 비율을 저장해야 하는데 저장 형식도 없다.
- 헷갈림 복습 중 목록이 바뀜 (-0.5). 헷갈림만 보기에서 `헷갈림 2 / 3` 질문의 표시를 끄면 그 질문이 목록에서 빠진다. 다음 질문이 무엇이 되는지, 위치 글이 `2 / 2` 로 바뀌는지 없다. 복습 세션 시작 때 목록을 고정해야 한다.
- 시뮬레이션과 질문 사이 왕복이 고리를 만듦 (-0.5). 질문 읽다가 동작으로 보기 → 시뮬레이션 끝에서 글로 정리하기(05-sim 3절)가 질문으로 앞으로 가기라서, 기록이 질문 → 시뮬레이션 → 질문으로 쌓인다. 뒤로를 누르면 시뮬레이션으로 되돌아간다. 질문으로 돌아올 때 답 펼침 상태와 스크롤을 되살리는 규칙도 03 에 없다.
- 목차에서 장 이동 수단이 없음 (-0.5). 00-system 10절이 과목 칩 줄을 머리가 두 줄이 된다는 이유로 뺐다. 현재 앱 스크린샷(after-390-toc-conf)에는 과목 칩이 있으니 기능 후퇴다. 40행 목차는 대략 4,000px(6화면)이라 네트워크 장까지 4~5번 튕겨야 하고, 02-toc 1절 목표인 3번 이내 눈길과 맞지 않는다. 근거로 든 iOS 연락처에서 가장 쓸모 있는 부분(옆 색인)은 가져오지 않았다.
- `빈출순` 이름과 동작이 다름 (-0.5). 02-toc 4절에서 빈출순은 별 있는 20문항만 보인다. 이름은 정렬인데 동작은 거르기라, 별 없는 질문이 사라진 이유를 끝 안내 문장으로 설명해야 한다. 한 분할 칩 안에 전체(보기), 빈출순(정렬), 헷갈림만(거르기)이 섞였다.

### 3. 모바일 가독성 (11 / 15)

- 좋은 점: 본문 17/30, 핵심 18/30, 소제목 19, 최소 12px, 메타 대비 4.6:1 이상, 코드와 표는 칸 안에서만 밀림(03-question 5.4). 오래 읽는 화면으로는 실서비스 수준이다.
- 고정 높이 카드가 내용보다 작음 (-1.5). 빈출 카드 232x152(01-home 4.5): 안쪽 16 + 꼬리표 줄 24 + 간격 12 + 제목 3줄 75 + 과목 줄 20 + 바닥 16 = 163 으로 제목과 과목 사이 간격이 0 이어도 11px 넘친다. 랜덤 카드 350x168(4.3)도 18 + 24 + 10 + 81 + 20 + 16 = 169 로 넘친다. 기기 글자 크기를 키우면 더 넘친다.
- 긴 제목 처리 없음 (-1). 실제 데이터에서 가장 긴 제목이 102자(`db-bplus`), 40자 넘는 것이 6개다. 빈출 카드 글 폭 200px 에 17px 이면 3줄에 약 35자라 별 4개인 1번 카드(`ds-collision`, 53자)가 가장 먼저 잘린다. 질문 상세 제목 24px 는 102자면 5~7줄이 되어 떠올리기 판이 첫 화면 밖으로 밀린다. 자리별 말줄임 규칙과 긴 제목용 크기 단계가 없다.
- 붙는 머리가 실제 화면에서 너무 큼 (-1). 목차는 머리 60(접힌 뒤) + 칩 56 + 얇은 장 머리 44 = 160px 이 붙는다. 사파리에서 iPhone SE 의 보이는 높이는 약 548px 이라 화면의 29% 가 머리다. 질문 상세는 위 59 + 아래 102 = 161px.
- 360 폭 넘침 (-0.5). 목차 장 머리(02-toc 4절): 그림 64 + 사이 16 + 블록 12칸(14x12 + 3x11 = 201) + 사이 + `10 / 12` 약 40 = 약 327px 인데 360 폭 글 자리는 320px 이다.

### 4. 모션 (8 / 10)

- 좋은 점: 움직임마다 무엇을 말하는지(00-system 7.3), 이징 5개와 시간 6단계, 세션당 1번, 움직임 줄이기가 화면마다 적혀 있다.
- 홈 미리보기 무한 반복에 정지 수단 없음 (-1). 01-home 6절 시뮬레이션 무대는 보일 때마다 계속 반복한다. 5초 넘게 자동으로 움직이는 내용에는 멈춤 수단이 있어야 한다(WCAG 2.2.2). 오른쪽 아래 재생 표시는 시뮬레이션으로 가는 링크라 멈춤이 아니다. 목록(04)처럼 몇 바퀴 뒤 포스터 프레임에서 멈추면 된다.
- 자동 재생 속도가 읽기 속도와 모순 (-0.5). 05-sim 6절은 글자당 80ms(분당 750자)인데 남은 시간 계산(01-home 4.2)은 분당 500자(글자당 120ms)다. 그림까지 봐야 하는 시뮬레이션이 글만 읽는 본문보다 빠르다.
- 보상이 읽기가 아니라 스크롤에 붙음 (-0.5). 03-question 5.6 읽음 기준은 다 읽음 영역 60% 노출이다. 짧은 답(가장 짧은 본문 388자)은 답 보기 후 한 번 튕기면 바로 `한 칸 쌓였어요` 와 튀어오름이 나온다. 보상이 흔해지면 의미가 사라진다.

### 5. 시스템 일관성 (7 / 10)

- 토큰 값이 문서끼리 다름 (-1.5): title-1 은 00-system 5.2 에서 24/32, 03-question 5.1 과 와이어프레임에서 24/34. h-read 굵기는 00 에서 680, 03 5.4 에서 700. display 는 00 에서 32/40, 01-home 4.4 에서 32/38. 하단 막대는 00 6.8 에서 102, 03 와이어프레임에서 98.
- 같은 다음 행동의 자리가 화면마다 다름 (-1): 질문의 다음 질문은 화면 아래 고정 막대(03 5.7), 시뮬레이션의 다음 단계는 본문 안 조작 줄(05 4절). 두 공부 화면에서 엄지가 가는 자리가 다르고, 시뮬레이션 쪽은 아래 6절처럼 첫 화면 밖으로 밀린다.
- 같은 대상 이름 둘 (-0.5): 탭은 시뮬레이션, 홈 섹션과 질문 입구는 동작으로 보기. 입구 문구로는 괜찮지만 홈 섹션 머리까지 다르면 탭과 섹션이 같은 곳이라는 연결이 약하다.

### 6. 구현 가능성 (6 / 10)

- 화면 전환 접근성 없음 (-1): 해시 주소로 화면이 바뀔 때 `document.title`, 초점 이동(새 화면 제목으로), 스크롤 처리 규칙이 없다. 초점 규칙은 답 보기(03 7절) 하나뿐이다.
- 접근 이름 문제 (-1): 히어로 전체가 링크 하나(01-home 4.2)라 화면 읽기가 조각 A, B, 과목, 제목, 메타, 버튼 글을 한 번에 링크 이름으로 읽는다. 짧은 `aria-label` 이 필요하다. 헷갈려요 버튼은 `aria-pressed` 와 글 바꿈(헷갈려요 → 헷갈림)을 같이 써서 눌림 상태가 두 번 말해진다. 진행 칸에는 역할과 읽기 글이 없다. 알림 한 줄과 저장 불가 줄에 `role=status` 가 없다.
- 실제 브라우저 조건 미설계 (-1): 하단 막대 아래 34 를 고정값으로 둠(00-system 6.8). 사파리 브라우저 안에서는 툴바가 그 자리를 이미 덮으므로 `env(safe-area-inset-bottom)` 로 바꿔야 한다. 공개 배포인데 데스크톱·태블릿 폭(가운데 정렬 최대 폭)과 가로 모드가 없다. 모든 부품 폭이 350 고정값이라 360 에서의 규칙(히어로 조각 B 가 그림을 얼마나 덮는지 등)이 없다.
- 저장 데이터 보호 (-1): 06-states 3.4 는 저장값 형식이 깨지면 조용히 빈 상태로 다시 시작한다. 문항 추가나 이름 변경 같은 배포 한 번에 사용자 진도가 통째로 사라질 수 있다. 버전 키와 옮기기, 모르는 id 만 버리기(현재 `app.js` 가 이미 하는 방식)가 필요하다.
- 본문 불러오기 상태를 잘못 적음 (-0): 06-states 3.1 은 글이 앱에 들어 있어 불러오기 화면이 없다고 하지만, 실제로는 `data/notes.json` 138KB 를 fetch 한다(`app.js` 301행). 느린 지하철 망에서 빈 화면, 실패 화면(현재 앱에는 `내용을 불러오지 못했어요` 가 있음)이 v2 설계에서 빠졌다. 감점은 8번 목록에서 합쳐 반영.

### 7. 레퍼런스 도입 (8 / 10)

- 좋은 점: 표마다 왜 도입하나 열이 있고, 넣지 않은 것과 이유(00-system 10절)까지 있다. Apple Books 남은 시간, Brilliant 덩어리 진행 막대, Duolingo 잠긴 노드를 빈 탑으로 바꾼 것은 학습 앱 맥락에 정확히 맞는다.

1. **이동과 상태 규칙 절을 00-system 에 새로 쓴다** (2번 항목 대부분 해결)
   - 진입 맥락 표: 진입로(히어로, 랜덤, 빈출 띠, 목차 전체/빈출/헷갈림, 탑에서 목차, 시뮬레이션 관련 질문, 글로 정리하기)마다 이전/다음 순서, 위치 글, 처음 답 상태(가림/펼침), 뒤로 목적지를 한 줄씩. 예: 랜덤과 히어로는 책 순서와 `5 / 9`, 빈출 띠는 빈출순 맥락과 `빈출 1 / 20`.

   - 시뮬레이션 왕복: 질문에서 들어온 시뮬레이션의 `글로 정리하기` 는 `history.back()` 으로 돌아가고, 질문은 떠날 때의 답 펼침과 스크롤을 되살린다. 질문 밖에서 들어온 경우만 새로 연다.
   - 이어 읽기 대상: 답을 펼치고 첫 덩어리를 지난 질문만 `last` 로 저장. 랜덤·빈출 카드로 열고 답을 안 펼친 채 떠나면 바꾸지 않는다. 답을 펼친 적 없는 `last` 는 답 가림으로 연다.
   - 상태 모델: 읽기 상태(안 읽음 / 읽는 중 n% / 읽음)와 헷갈림(켬/끔)은 서로 독립. `10 / 12` 는 읽음 수(헷갈림 포함), 탑 블록은 헷갈림이 우선해 속 빈 빨강으로 그린다는 식으로 한 표에. 저장 형식(`v`, `read`, `pct{id:n}`, `confused`, `last{id, chunk, revealed}`)도 함께.
   - 헷갈림 복습: 헷갈림만 보기에서 들어간 순간 목록을 고정. 중간에 표시를 꺼도 그 세션의 이전/다음과 `n / N` 은 그대로, 목록 화면에 돌아올 때만 빠진다.

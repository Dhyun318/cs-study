# design/landing/ 랜딩 시안

사이트 첫 주소(/)에 둘 랜딩 페이지 시안. 앱은 /app/. 파일 하나(`index.html`, CSS·JS 포함, 의존성 없음).

## 결정 (2026-11-14)
- 모션은 폰 프레임 안에서 실제 앱 화면이 움직이는 소개다. 추상 CS 모션은 쓰지 않는다(식상함, 사용자 결정). 버린 것은 CS 개념 모션 스플래시이고, 사진 컷 스플래시는 아래처럼 넣었다.
- 스플래시(2026-11-14 사용자 요청: 오픽 앱 로딩처럼 사진 여러 장이 휘리릭 넘어가는 것, 휴대폰에서 더 잘 먹힘). 오픽 `spike/design/final/index.html` 의 R1 스플래시 시간표를 그대로 옮기고 창 모양과 마크만 우리 것.
  - 시간표: 0~0.3초 마크 모양 창(둥근 사각, 모서리 32 중 7)이 열리며 첫 사진 / 0.3·0.43·0.54·0.64·0.74초 사진이 점점 빨리 바뀜(확대·블러에서 또렷하게), 창 위 칩 `읽음 3/40 → 40/40`, 창 아래 링이 차오르고 `자료구조부터 네트워크까지` / 0.95초 창이 남색(마크 바탕 #03257B)으로 차고 1.02·1.07·1.12초 막대 3개가 아래부터 쌓여 마크가 됨 / 1.05~1.4초 마크 크기(104)로 줄고, 다 줄어든 뒤 1.2·1.24초에 `CS 차곡`, `CS 전공 개념을 차곡차곡` 이 올라옴(1회차 평가: 1.12초에 올라오면 큰 마크 아래와 겹쳐 보였음) / 1.4초 120ms 사라짐(약 1.52초에 끝).
  - 칩은 과목 이름 대신 읽음 n/40 을 골랐다: 6컷에 4과목이면 이름이 겹치고, 40/40 으로 차오르는 것이 창이 차서 마크가 되는 것과 이어진다. 링 글은 오픽의 2:00 처럼 고정 글.
  - 언제: 휴대폰(959 이하)에서 세션마다 한 번(sessionStorage `cs-sp`), 움직임 줄이기면 없음, 컴퓨터는 없음. 결정은 머리 스크립트에서 첫 그리기 전에(뷰포트 메타가 그보다 위에 있어야 휴대폰 폭으로 잰다). 공부 기록이 있어도 보여 주고 시작하기 글 바꾸기는 그대로.
  - 아무 곳이나 누르면 바로 건너뜀(click 으로 받아 뒤의 시작하기가 같이 눌리지 않게). 도는 동안 스크롤 잠금(html overflow hidden + 덮개 touch-action none), 끝나면 풀고 첫 화면(제목, 시작하기)이 바로 보인다(랜딩 등장 움직임은 스플래시 뒤에서 이미 끝남).
  - 사진: `photos/sp/photo-1~6.webp`(원본 `photos/photo-1~6.webp` 1170x1500, 6장 약 0.96MB 를 창과 같은 가운데 정사각으로 잘라 840x840 webp 로 줄인 사본, 장당 약 60KB, 합 약 0.36MB. 2026-11-15 UX 2회차: 느린 망(Fast 3G)에서 스플래시 동안 사진 0장이었음. 원본은 코덱스 것이라 그대로 두고 사본만 만든다. 만드는 법: PIL 로 `crop((0, (h-w)//2, w, (h-w)//2+w)).resize((840, 840), LANCZOS)` 뒤 62KB 이하가 되는 가장 높은 quality 로 `WEBP method=6` 저장). 기다리지 않고 바로 시작하고 불러온 컷만 보인다(못 불러오면 연한 판 색). 5·6 이 없으면 1·2 로 채운다(onerror). 시간은 첫 그리기(requestAnimationFrame)부터 잰다. `scripts/assemble_site.py` 가 `photos/*.webp` 와 `photos/sp/*.webp` 를 같은 상대 경로로 dist 에 복사한다.
  - 낮거나 좁은 화면(가로로 든 휴대폰 등)은 통째로 줄인다(높이 560, 폭 340 기준).
- 장면 5개: 답 가림 펼침, 읽은 만큼 진행 칸, 홈 탑 블록 쌓기, TCP 3-way 시뮬레이션, 헷갈려요 표시 후 목차 헷갈림만 거르기. 넓은 화면과 좁은 화면이 같은 장면, 같은 문구를 쓴다.
- 넓은 화면(960 이상): 폰이 오른쪽에 붙고 왼쪽 설명을 스크롤하면 장면이 바뀐다(IntersectionObserver, 스크롤 리스너 없음). 꺼진 걸음은 투명도 대신 흐린 색(제목 ink-off 3:1, 본문 ink-3 4.6:1, 투명도 .28 은 1.8:1 이었음).
  - 첫 화면 글 묶음은 폰과 세로 가운데. 시작하기 아래 `휴대폰으로 열기` QR(앱 주소 `https://cs-study-sooty.vercel.app/app/`, 96px). 휴대폰 공부 앱이라 컴퓨터 방문자가 넘어갈 길이 필요. QR 은 외부 API 없이 segno(파이썬)로 미리 만든 정적 SVG 를 넣었다: `pip install --target /tmp/qrlib segno` 뒤 `segno.make(주소, error='m').save(..., kind='svg', border=2, dark='#191F28')`. 주소가 바뀌면 다시 만든다.
- 실제 서비스 랜딩처럼 스크롤 랜딩(2026-11-14 사용자 결정: 지금 랜딩이 실제 랜딩 느낌이 아니다). 두 화면 같은 순서: 첫 화면 -> 기능 5개 -> 과목(머리에 숫자 4칸) -> 자주 묻는 질문 -> 끝 시작하기 -> 바닥글. 고른 레퍼런스와 이유는 `REFERENCES.md`(스크린샷 `_refs/` 는 git·배포 제외).
  - 2026-11-15 디자인 2회차: 따로 선 숫자 띠를 과목 섹션 머리로 합쳤다. 숫자 띠라는 형식이 SaaS 템플릿 신호였고, 40·30 은 첫 화면, 과목별 수는 과목 meta 와 세 번 겹쳤다. 과목 내역 바로 위에 서면 숫자를 아래 내역이 풀어 보여 줘 겹침이 근거가 된다.
  - 기능 5개: 넓은 화면 걸음 5개와 같은 목록, 같은 문구. 넓은 화면은 붙은 폰이 장면을 보여 주고, 좁은 화면은 걸음마다 앱 화면 조각(`.lp-frag`: 연회색 판 반경 24 안에 390 폭 앱 부품을 그대로 그려 `--fz`=(화면 폭-80)/390 배로 zoom, 아래가 판 끝에서 잘림, toss 방식)을 둔다. 조각은 답 보기 카드, 이어 읽기 카드(진행 칸까지, 버튼 없음), 과목 진도 탑, TCP 시뮬레이션 끝 단계, 헷갈림만 거른 목차.
  - 묶음 제목 `이렇게 공부해요`(h2, 섹션 제목과 같은 28px, 위 72 아래 32): 휴대폰은 첫 화면 끝 한 줄(지금 장면 제목)과 걸음 1 제목이 같은 문장이라 묶음 경계가 없었다(2026-11-15 두 평가 2회차. 디자인은 13px 머리글, UX 는 섹션 제목을 제안했고 하나로 합쳐 다른 섹션과 같은 28/22 위계를 따르는 섹션 제목으로). 컴퓨터는 걸음이 폰에 붙어 있어 화면에서 숨기고(제목 순서만 남기는 숨김, 절대 위치라 grid 칸을 안 차지함), 걸음 제목은 그 아래 h3.

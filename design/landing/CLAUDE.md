# design/landing/ 랜딩 시안

사이트 첫 주소(/)에 둘 랜딩 페이지 시안. 앱은 /app/. 파일 하나(`index.html`, CSS·JS 포함, 의존성 없음).

## 결정 (2026-11-14)
- 모션은 폰 프레임 안에서 실제 앱 화면이 움직이는 소개다. 추상 CS 모션은 쓰지 않는다(식상함, 사용자 결정). 버린 것은 CS 개념 모션 스플래시이고, 사진 컷 스플래시는 아래처럼 넣었다.
- 스플래시(2026-11-14 사용자 요청: 오픽 앱 로딩처럼 사진 여러 장이 휘리릭 넘어가는 것, 휴대폰에서 더 잘 먹힘). 오픽 `spike/design/final/index.html` 의 R1 스플래시 시간표를 그대로 옮기고 창 모양과 마크만 우리 것.
  - 시간표: 0~0.3초 마크 모양 창(둥근 사각, 모서리 32 중 7)이 열리며 첫 사진 / 0.3·0.43·0.54·0.64·0.74초 사진이 점점 빨리 바뀜(확대·블러에서 또렷하게), 창 위 칩 `읽음 3/40 → 40/40`, 창 아래 링이 차오르고 `자료구조부터 네트워크까지` / 0.95초 창이 남색(마크 바탕 #03257B)으로 차고 1.02·1.07·1.12초 막대 3개가 아래부터 쌓여 마크가 됨 / 1.05~1.4초 마크 크기(104)로 줄며 `CS 차곡`, `CS 전공 개념을 차곡차곡` 이 올라옴 / 1.4초 120ms 사라짐(약 1.52초에 끝).
  - 칩은 과목 이름 대신 읽음 n/40 을 골랐다: 6컷에 4과목이면 이름이 겹치고, 40/40 으로 차오르는 것이 창이 차서 마크가 되는 것과 이어진다. 링 글은 오픽의 2:00 처럼 고정 글.
  - 언제: 휴대폰(959 이하)에서 세션마다 한 번(sessionStorage `cs-sp`), 움직임 줄이기면 없음, 컴퓨터는 없음. 결정은 머리 스크립트에서 첫 그리기 전에(뷰포트 메타가 그보다 위에 있어야 휴대폰 폭으로 잰다). 공부 기록이 있어도 보여 주고 시작하기 글 바꾸기는 그대로.
  - 아무 곳이나 누르면 바로 건너뜀(click 으로 받아 뒤의 시작하기가 같이 눌리지 않게). 도는 동안 스크롤 잠금(html overflow hidden + 덮개 touch-action none), 끝나면 풀고 첫 화면(제목, 시작하기)이 바로 보인다(랜딩 등장 움직임은 스플래시 뒤에서 이미 끝남).
  - 사진: `photos/photo-1~6.webp`. 기다리지 않고 바로 시작하고 불러온 컷만 보인다(못 불러오면 연한 판 색). 5·6 이 없으면 1·2 로 채운다(onerror). 시간은 첫 그리기(requestAnimationFrame)부터 잰다.
  - 낮거나 좁은 화면(가로로 든 휴대폰 등)은 통째로 줄인다(높이 560, 폭 340 기준).
- 장면 5개: 답 가림 펼침, 읽은 만큼 진행 칸, 홈 탑 블록 쌓기, TCP 3-way 시뮬레이션, 헷갈려요 표시 후 목차 헷갈림만 거르기. 넓은 화면과 좁은 화면이 같은 장면, 같은 문구를 쓴다.
- 넓은 화면(960 이상): 폰이 오른쪽에 붙고 왼쪽 설명을 스크롤하면 장면이 바뀐다(IntersectionObserver, 스크롤 리스너 없음).
- 좁은 화면(959 이하): 스크롤 없는 한 화면에서 폰 속 장면이 자동으로 넘어간다(2026-11-14 사용자 결정). 위에서부터 제목, 한 줄 설명, 시작하기, 폰, 폰 아래 점 5개(누르는 영역 44)와 지금 장면 한 줄(넓은 화면 걸음 제목과 같은 문구). 세로 스크롤 0(390x844, 360x780, 375x667 모두). 설명 걸음, 과목 소개, 끝 섹션, 바닥글은 넓은 화면 전용.
  - 이유: 스크롤 걸음은 내려야만 장면이 바뀌고, 폰과 설명 글이 한 화면을 나눠 써서 폰이 화면 높이의 46% 로 작았다. 자동 재생은 손대지 않아도 장면 5개가 다 지나가고, 첫 화면 하나로 소개가 끝난다.
  - 폰 크기: 시작하기 아래 남은 높이에서 점과 한 줄(98)을 뺀 만큼 폰만 줄인다(`fit()`, 최대 0.66, 글자·버튼은 그대로). 0.2 보다 작아야 하는 아주 낮은 화면(가로로 든 휴대폰)은 0.2 에서 멈추고 스크롤을 허용한다.
  - 자동 재생: 장면마다 기존 움직임(DUR)이 끝나고 1.4초 멈춘 뒤 다음, 5 다음은 1(한 바퀴 약 21초). 7f4e32b 의 한 화면 자동 재생을 가져왔다.
  - 점을 누르면 그 장면을 처음부터 끝까지 보여 주고, 자동 재생은 거기서부터 이어진다(멈추지 않음, 사용자 결정). 다른 화면에서 바로 질문 장면 2 로 오면 답 맨 위에서 시작한다.
  - 탭이 안 보이면 멈추고, 다시 보이면 그 장면 처음부터 이어서 자동 재생.
  - 스플래시가 도는 동안은 자동 재생을 시작하지 않고(폰은 홈 그림), 스플래시가 끝나면(`sp-end` 이벤트) 첫 장면부터.
  - 움직임 줄이기: 자동 재생 없이 점으로만 넘기고, 장면은 끝 상태 그림.
  - 버린 안: 넓은 화면과 같은 스크롤 걸음(폰이 머리 아래 sticky, 설명 글이 폰 아래 sticky 로 붙었다 밀림, 9d60c61). 위 이유로 2026-11-14 사용자 결정으로 바꿨다.
  - 버린 안: 오픽 온보딩처럼 가로로 넘기는 소개 4장(사진 + 앱 조각, 건너뛰기, 다음, 9dbaac9). 2026-11-14 사용자 결정으로 뺐다. 사진 `photos/`(코덱스 AI 사진, 설명 `photos/README.md`, 코덱스 것이라 고치지 않는다)는 스플래시에서 쓴다.
  - 버린 안: 점을 누르면 자동 재생이 멈추는 한 화면 자동 재생(7f4e32b). 사용자는 계속 자동으로 넘어가길 원해서 점을 눌러도 이어지게 바꿨다.
- 움직임 줄이기: 두 화면 모두 장면은 끝 상태 그림.
- 폰 안 화면은 `../v2/index.html` 부품 CSS 를 옮겨 정적 HTML 로 그리고 통째로 줄인다(데이터 로딩 없음). 시뮬레이션도 iframe 이 아닌 정적 사본(문구는 `sims/tcp-handshake` 와 같음).
- 폰 안 움직임 시간은 앱 토큰(spec/00 9절) 그대로. 단 탑 블록 쌓기 간격만 24ms 대신 60ms(폰이 줄어 있어 24ms 면 안 보임). 랜딩 등장은 references-rea.md 의 dur-enter 420ms, dur-hero 800ms.
- 공부 기록(localStorage `cs-chagok`)이 있어도 자동으로 넘기지 않고, 시작하기 버튼 글만 `이어서 공부하기`로 바꾼다(머리, 첫 화면, 끝 버튼 모두). 2026-11-14 사용자 결정: 다시 온 사람도 랜딩을 볼 수 있게.
- 로고(머리의 CS 차곡)는 다시 불러오지 않고 맨 위로 돌아간다(좁은 화면은 스크롤이 없어 그대로 맨 위).
- 문구에 쓰지 않는 것: 로그인, 동기화, 알림, 검색, 면접 연출. 교재·출판사 이름.

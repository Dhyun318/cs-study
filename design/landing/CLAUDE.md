# design/landing/ 랜딩 시안

사이트 첫 주소(/)에 둘 랜딩 페이지 시안. 앱은 /app/. 파일 하나(`index.html`, CSS·JS 포함, 의존성 없음).

## 결정 (2026-11-14)
- 모션은 폰 프레임 안에서 실제 앱 화면이 움직이는 소개다. 추상 CS 모션, 스플래시, 온보딩은 쓰지 않는다(식상함, 사용자 결정).
- 장면 5개: 답 가림 펼침, 읽은 만큼 진행 칸, 홈 탑 블록 쌓기, TCP 3-way 시뮬레이션, 헷갈려요 표시 후 목차 헷갈림만 거르기.
- 넓은 화면(960 이상): 폰이 오른쪽에 붙고 왼쪽 설명을 스크롤하면 장면이 바뀐다(IntersectionObserver, 스크롤 리스너 없음).
- 좁은 화면(959 이하): 긴 스크롤 대신 한 화면 자동 재생(사용자 결정). 제목, 부제, 시작하기, 폰, 장면 점 5개, 한 줄 설명. 점을 누르면 자동 재생 멈춤, 탭이 안 보이면 멈춤. 과목 소개는 빼고 마지막 섹션은 한 줄 안내만. 이유: 휴대폰에서 긴 스크롤은 시작하기까지 멀다.
- 움직임 줄이기: 자동 재생 없음, 장면은 끝 상태 그림, 점으로만 넘긴다.
- 폰 안 화면은 `../v2/index.html` 부품 CSS 를 옮겨 정적 HTML 로 그리고 통째로 줄인다(데이터 로딩 없음). 시뮬레이션도 iframe 이 아닌 정적 사본(문구는 `sims/tcp-handshake` 와 같음).
- 폰 안 움직임 시간은 앱 토큰(spec/00 9절) 그대로. 단 탑 블록 쌓기 간격만 24ms 대신 60ms(폰이 줄어 있어 24ms 면 안 보임). 랜딩 등장은 references-rea.md 의 dur-enter 420ms, dur-hero 800ms.
- 공부 기록(localStorage `cs-chagok`)이 있으면 head 의 한 줄 스크립트가 `./app/` 으로 보낸다. 시안 확인은 `?stay=1`.
- 문구에 쓰지 않는 것: 로그인, 동기화, 알림, 검색, 면접 연출. 교재·출판사 이름.
